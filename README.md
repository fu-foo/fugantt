# fugantt

**予定と実施を並べ、営業日で数えるガントチャート。**
Excel と同じキー操作で編集できる。Rust（Topcoat + SQLite）製、実行ファイル1本。

[English](README.en.md)

![スケジュール画面](docs/images/schedule.png)

## できること

- **予定と実施が同じ行にある。** 開始差異・終了差異は保存せず、毎回計算する
- **遅れは入れた予定に対して出る。** 「この日までに何%」を入れた行だけ、届かなければ赤
- **遅れの内訳が出る。** 「12日遅れ」ではなく「作業9日、待ち3日」
- **誰が空いているか分かる。** 月単位で、埋まっている日数・空き日数と、その日付
- **取り消せる。** ⌘Z / Ctrl+Z。他の人が先に触ったセルは取り消さない
- **日数の数え方を選べる。** 土日・祝日・休暇・待ちを除く（既定で除く）
- **日本の暦に合っている。** 祝日は計算（振替休日・国民の休日まで）、年度、和暦、土曜は青・日曜は赤
- **キーボードで編集する。** 日本語入力もそのまま通る
- **Excel と JSON に書き出す。** JSON は取り込みもできる
- **既定は日本語。** ブラウザが英語なら英語で出る

## 動かす

```sh
cargo-topcoat dev        # 開発。http://127.0.0.1:3000
cargo build --release    # 配布用の実行ファイル1本
```

設定は環境変数か、**`fugantt.ini`**（実行ファイルの隣・カレント・利用者ごとの場所のどれか）。
書く名前はどちらも同じ。**環境変数のほうが強い**（Docker と Fly は環境変数で渡す）。

```ini
# fugantt.ini
PORT = 3100
FUGANTT_DB = D:\plans\fugantt.db
```

`fugantt --config` でどの値がどこから来ているか、`fugantt --help` で書ける項目が出る。
`fugantt.conf` と `.env` も読む。

| 環境変数 / `fugantt.ini` | 既定 | |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | `0.0.0.0` で LAN に公開 |
| `PORT` | `3000` | |
| `FUGANTT_DB` | 下記 | SQLite ファイル。起動時に自動でマイグレーション |
| `FUGANTT_OPEN` | `window` / `tab` | 起動時に画面を開く。`0` で開かない |
| `FUGANTT_ALLOW_HTTP` | — | `1` で平文 HTTP を許可（後述） |

**起動すると画面が開く。** Windows は Edge のアプリウィンドウ（アドレスバー無し）、
他は既定のブラウザのタブ。127.0.0.1 に立てたときだけで、`0.0.0.0` なら開かない。

**DB の場所**は、`FUGANTT_DB` →（カレントに `fugantt.db` があればそれ）→ 利用者ごとの場所、の順。
最後は Windows が `%LOCALAPPDATA%\fugantt`、macOS が `~/Library/Application Support/fugantt`、
Linux が `~/.local/share/fugantt`。起動時に絶対パスを1行出す。
**すでに `fugantt.db` を置いて使っているなら、そのまま**。実行ファイルを差し替えても場所は動かない。

```sh
brew install fu-foo/tap/fugantt                    # macOS / Linux
scoop bucket add fu-foo https://github.com/fu-foo/scoop-bucket && scoop install fugantt

docker run -p 3000:3000 -v fugantt:/data ghcr.io/fu-foo/fugantt
```

[Releases](https://github.com/fu-foo/fugantt/releases) に4つ。**Apple Silicon はネイティブ**で、
`brew` も M シリーズには arm64 版を入れる（Rosetta は要らない）。

| | |
| --- | --- |
| `fugantt-macos-arm64` | macOS / Apple Silicon |
| `fugantt-macos-x86_64` | macOS / Intel |
| `fugantt-windows-x86_64` | Windows 64bit（C ランタイムも静的リンク。単品で動く） |
| `fugantt-linux-x86_64` | Linux 64bit（glibc） |

**Docker イメージだけは amd64 のみ。** Apple Silicon で動かすなら `--platform linux/amd64`
を付ける（エミュレーションで動く）。arm64 を出していないのは、CI で QEMU 越しに Rust の
リリースビルドを回すと、リリースを切るのが億劫になる時間がかかるため。ネイティブで動かしたい
なら上のバイナリか、`cargo build --release` を。

Fly.io の設定も入っている（`fly.toml`）。

> `cargo topcoat dev` ではなく `cargo-topcoat dev`。topcoat-cli 0.5.0 は
> cargo のサブコマンドとして呼ばれると引数を読めない。`cargo run` でも動く。

### 社内 LAN に置くとき

セッションクッキーには既定で `Secure` と `__Host-` が付く。ブラウザは localhost 以外の
`http://` から `Secure` クッキーを受け取らないので、そのままでは LAN の IP でログインできない。

`FUGANTT_ALLOW_HTTP=1` で `Secure` を外せる。トークンは平文で流れる。起動時に警告が出る。
HTTPS を用意できるならそのほうがいい（Caddy の `tls internal`、Tailscale の証明書）。

### 運用

- **バックアップは全体の設定から。** 「バックアップを作る」で1ファイル落ちてくる。戻すのも同じ画面
  （戻す直前の中身は、データベースの隣に自動で1つ控える）。**アカウントとパスワードもその時点に戻る**

## 操作

| キー | |
| --- | --- |
| 矢印 | セル移動 |
| Tab / Shift+Tab | 前後のセルへ。行末で次の行へ回り込む |
| Enter / F2 / ダブルクリック | 編集を開く |
| 文字入力 | その文字で編集開始（日本語変換を含む） |
| Esc | 編集を取消 |
| Enter / Tab（編集中） | 確定して下 / 右へ |
| Delete / Backspace | セルを空にする |
| ⌘Enter / Ctrl+Enter | 下に行を追加 |
| ⌘Delete / Ctrl+Delete | 行を削除（子タスクも消える） |
| Home / End | 行の先頭 / 末尾。⌘ / Ctrl 併用で表の先頭 / 末尾 |
| ⌥→ ← / Alt+→ ← | 子にする / 階層を戻す |
| ⌥↑ ↓ / Alt+↑ ↓ | 兄弟の中で並べ替え |
| ⌘← → / Ctrl+← → | 折りたたむ / 展開する |
| ⌘Z / Ctrl+Z | 直前の変更を取り消す |
| ⌘Y / ⌘⇧Z / Ctrl+Y | やり直す |

`⌘` と `Ctrl` はどちらでも効く。OS で変わるのは画面の表記だけ。右クリックで同じ操作のメニューが出る。
**行の色**（背景・文字）もそのメニューから。★ や【重要】をタスク名に書かなくて済むように。

バーはドラッグで動く。端（7px）をつまむと開始日・終了日だけ伸縮する。実施バーも同じ。
ただし進行中（実施終了が空）の行は、横に動かしても終了日を作らない。
進捗は予定バーの中のつまみで変える。

日付は `20260805` `8/5` `2026-08-05` のどれでも通る。全角のままでもいい。

取り消せるのは**この画面でした値の変更**だけ。間に他の人が同じセルを触っていたら止めて知らせる
（他人の変更を消さない）。行の追加・削除・並べ替えは取り消せない。リロードすると履歴は消える。

## 予定と実施

日付は **予定開始・予定終了・実施開始・実施終了** の4つ。**開始差異**と**終了差異**は保存せず、
毎回引き算で出す。チャートは予定が枠、実施がその下の実線。

- **進捗の塗りは予定バーの中。** 実施バーには乗らない
- **待ち**は期間と理由で登録する。その日数は日数からも遅延判定からも外れる
- **休暇と出社**はスケジュール画面のボタンから。休暇は人につくので、その人の全プロジェクトに効く

進捗は自動計算しない（暦から出すと遅れが立たなくなるため）。「ステータスに連動」を選べば、
その状態に決めた進捗が入る。どちらでも 100% にすると、実施終了が空なら今日が入る。

### 予定進捗

**この日までに何%**を、待ちと同じダイアログで入れる。その日を過ぎて実進捗が届いていなければ
赤くなる。**点と点の間は判定しない**——8/20 に 30%、8/28 に 100% と入れたなら、見るのは
その2日だけ。間を直線で結ぶのは、誰も立てていない計画を発明することになる。

チャートでは、足りない分が**塗りの続きの帯**として出て、その端に **`8/5 50%`** と書く。
帯の端は「バーの半分＝50%」の位置。日付の位置ではない——このバーは掴むと進捗を入れる装置に
なるので、横軸は％として読まれる。**比べるもの同士を同じものさしに乗せる**ということ。
達成すると帯は消えて青に戻る。まだ来ていない予定は細い印で出る。`表示`から消せる。

**入れなければ何も言わない。** 遅れは、日数から割り出すものではなく、立てた予定に対して出る。
線を引きたいだけなら、入れなくていい。

期限超過（予定終了を過ぎて実施終了が空）は日付の事実なので、予定進捗が無くても赤くなる。

### 遅延

**遅延は列**（タスクのすぐ右）。遅れている行にだけ赤い印が付く。列なので**絞り込める**——
「遅れている行だけ見せて」は、色では答えられない。赤くなる理由は2つ:

- 入れた**予定進捗**に届いていない
- **期限超過**（予定終了を過ぎて実施終了が空）。予定進捗が無くてもこちらは効く

## 余力

「山田は今月どれくらい空いているか」を、チャートを指で追わずに出す。月単位、任意の範囲。

| 担当者 | 稼働できる | 埋まっている | 空き | 重なり | |
| --- | --- | --- | --- | --- | --- |
| 佐藤 | 31日 | 22日 | **9日** | 5日 | 空き: 8/1〜8/9 ／ 重なり: 8/24〜8/28 |
| （未割当） | — | 20日 | — | — | |

- **1日は1日。** 同じ日に3件あっても1日。何重かは「重なり」に別立てで出す
  （合計すると 300% のような数字になって、誰も読まなくなる）
- **終わったタスクと集計行は数えない。** 休暇はその人の稼働から引く
- **空きと重なりは日付も出す。**「9日空いている」は答えの半分
- **未割当**も1行。誰も持っていない仕事が見えないと計画にならない

工数の％は持たない。1日の粒度より細かくするには全タスクに数字が要り、それは誰も更新しない。

## 絞り込み

見出しの上に、列ごとに1つ。複数埋めれば AND。日付と数値は欄の左のボタンで
**以上・以下・一致・超過・未満**を選ぶ（`100以下` `>=3` と打っても同じ）。
遅延の列は**遅延／順調**から選ぶだけ。

## 設定

会社として決まっていることは**全体**に、その計画のことは**プロジェクト**に置く。

| 全体（管理者） | プロジェクト |
| --- | --- |
| 祝日・休業日 | この現場だけの休み／「全体は休みだがここは動く」日 |
| 担当者の色 | この計画に出てくる担当者 |
| 担当者の休暇・出社 | 列・独自項目・表示・メモ・メンバー |
| 既定のステータス（作成時に**写す**） | そのプロジェクトのステータス |
| パスワードの決まり・アプリ名・元号・言語 | |
| バックアップの作成・復元 | |

祝日は「全体 ＋ この計画で足した日 − この計画で外した日」。
ステータスは参照ではなく写し。全体を直しても、既にあるプロジェクトは動かない。

| プロジェクトの設定 | |
| --- | --- |
| 表示 | 日数から除く日、年度の開始月、和暦、四半期、1日の幅 |
| 列 | 表示・幅・並び順。組み込み列と独自項目をまとめて扱う。タスク名は先頭で固定 |
| ステータス | 名前・色・その状態が意味する進捗（空なら手入力のまま）・並び順 |
| 独自の項目 | フリー・選択・フリー＋選択・日付・数値。**名前はあとから直せる**（値はそのまま）。種類を変えられるのは、その列が空のときだけ |
| 色 | 予定・完了分・実施・集計行・遅延・今日・土曜・日曜・祝日・休暇・待ち |
| メンバー | オーナー・編集者・閲覧者 |

## 書き出しと取り込み

Excel は読むため、JSON は持ち運ぶため。JSON にはプロジェクトの全部——設定・名簿・暦・タスク——が入る。
**タスクだけ**も出せる（ドロワーの「JSON で書き出す（タスク）」、API なら `?settings=0`）。
設定の無いファイルもそのまま取り込める——書いていない部分については何も言わない、というだけ。

```json
{
  "version": 1,
  "name": "リリース計画",
  "tasks": [
    { "id": "c0ffee…", "name": "要件定義", "depth": 0,
      "start": "2026-08-03", "end": "2026-08-14",
      "actual_start": "2026-08-03", "actual_end": "2026-08-18",
      "progress": 100, "status": "完了", "assignee": "山田",
      "waits": ["2026-08-17/2026-08-21"], "targets": ["2026-08-10/50"],
      "fields": { "製品": "A" } }
  ]
}
```

| | |
| --- | --- |
| `depth` | 0 から。1つ上の行より深ければその子 |
| `waits` | `開始/終了`。終わりを省けば、まだ待っている |
| `targets` | `日付/％`。予定進捗。無ければ、その行は進捗では遅れにならない |
| `id` | あれば更新、無ければ追加、ファイルに無い行は削除。手で書くなら省いていい |
| 参照 | ステータスも担当者も独自項目も、id ではなく名前 |
| 集計行 | 子から決まるので日付と進捗は書き出さない |

日数・差異・遅延はファイルに入らない。読みたいときは `GET /api/projects/{id}/grid` が計算済みで返す。

> 読むのは grid、書くのは JSON。

## API トークン

設定 → API トークンで、オーナーが発行する。**1つのプロジェクトだけ**を開ける鍵。
発行時に一度だけ表示する（保存するのはハッシュ）。権限は「読むだけ」と「読み書き」。

```sh
curl -H "Authorization: Bearer fug_…" \
  https://example.com/api/projects/release-plan/document          # 読む

curl -X POST -H "Authorization: Bearer fug_…" \
  -H "Content-Type: application/json" --data @plan.json \
  https://example.com/api/projects/release-plan/document          # 書き戻す
```

他のプロジェクトの鍵、読むだけの鍵での書き込み、鍵もクッキーも無い要求は、すべて **403**。
トークンで書いた変更は、変更履歴に **`API <トークンの用途>`** として残る。人の名前は付かない。

案件をまたぐなら、全体の設定で**全プロジェクトに効く鍵**を発行する（管理者だけ）。

```sh
curl -H "Authorization: Bearer fug_…" https://example.com/api/projects   # 計画の一覧
curl -H "Authorization: Bearer fug_…" https://example.com/api/summary    # 案件ごとの数字
```

`/api/summary` は統計画面と同じ計算を、プロジェクト単位で返す
（`late_days + wait_days = slipped`）。この2つはログイン中のセッションでも叩けて、
その場合は自分が見られるプロジェクトだけが返る。

## 権限と認証

- **ベース権限の「編集者」「閲覧者」は全プロジェクトに効く。** 案件ごとに分けるなら、
  ベースは「無効」にしてメンバーに追加する
- パスワードの決まり（最低文字数・必要な文字種・使わせない語）は全体の設定で決める
- パスワードを変えると、その人の他のセッションは切れる

`FUGANTT_NO_AUTH=yes-everyone-on-this-network-can-edit` で認証なしにもできる。
**その URL に届く人は全員が全プロジェクトを読み書きできる。** 動いている間は画面の上に帯が出る。
