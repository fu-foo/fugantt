# fugantt

Excel 的なキーボード操作でガントチャートを編集する Web アプリ。
サーバーは Rust（Topcoat + SQLite）、グリッドだけがブラウザ側の TypeScript。

![スケジュール画面](docs/images/schedule.png)

## できること

Excel のガント表でやっていたことを、Excel の速さのまま置き換えるために作った。

- **キーボードで編集する。** 矢印で移動、Enter で開く、Tab で右へ。日本語入力もそのまま通る
- **予定と実施を1行で持つ。** 開始差異・終了差異は保存せず、毎回引き算で出す。チャートでは予定が破線の枠、実施がその中の実線
- **日本の暦がはじめから正しい。** 祝日は計算（振替休日・国民の休日まで）、土曜は青・日曜は赤、年度は4月始まり、和暦、営業日での日数
- **担当者の休暇。** その人が休んでいる日は、その人のタスクの日数にも遅延判定にも入らない。休暇は人につくので、全部の計画に一度で効く
- **Excel と JSON に書き出せる。** Excel は画面と同じ列と、日ごとのセルで描いたチャート
- **共同編集。** 誰かの変更はその場で他の画面に届く
- **EXE 1本で動く。** 静的ファイルもバイナリに入っている。置くのは実行ファイルとデータベースだけ

| 画面 | |
| --- | --- |
| 統計 | ![統計](docs/images/stats.png) |
| 変更履歴 | ![変更履歴](docs/images/history.png) |

設定は[プロジェクトごと](docs/images/settings.png)。ステータスの種類・色・進捗、独自の項目、
表示する列、固定する列、年度の開始月まで、画面から変えられる。会社の暦（祝日）と担当者の色、
担当者の休暇は**全体で一つ**。

## 動かす

```sh
cargo-topcoat dev
```

`http://127.0.0.1:3000` で起動する。データベースは `FUGANTT_DB`（既定 `fugantt.db`）に作られ、
初回起動時にマイグレーションが走る。

## 社内 LAN に置く

```sh
HOST=0.0.0.0 PORT=3000 FUGANTT_ALLOW_HTTP=1 FUGANTT_DB=/var/lib/fugantt.db ./fugantt
```

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | `0.0.0.0` で LAN に公開 |
| `PORT` | `3000` | |
| `FUGANTT_DB` | `fugantt.db` | SQLite ファイル |
| `FUGANTT_ALLOW_HTTP` | — | `1` で平文 HTTP を許可 |

### FUGANTT_ALLOW_HTTP について

セッションクッキーは既定で `Secure` + `__Host-` を付ける。**ブラウザは localhost 以外の
`http://` から `Secure` クッキーを受け取らない**ので、そのままでは LAN の IP でログインできない。

`FUGANTT_ALLOW_HTTP=1` を立てると `Secure` を外し、名前も `session` に変える
（`__Host-` は `Secure` を必須とするため、片方だけでは弾かれる）。
セッショントークンは平文で流れる。その接続の中身は元々すべて平文なので、
**信頼できるネットワークでのみ**使うこと。起動時に警告を出す。

HTTPS を用意できるなら、そちらが正しい。Caddy のリバースプロキシ（`tls internal`）か
Tailscale の証明書が手軽。

### 配布物

**EXE 1本。** CSS・JS・favicon はバイナリに埋め込んである（`src/static_files.rs`）。
`/static/<内容のハッシュ>/<名前>` で配り、ビルドが変われば URL も変わるので
`immutable` キャッシュが嘘にならない。

DB のバックアップはファイルコピーではなく `VACUUM INTO` を使う（WAL のため）。

> `cargo topcoat dev` ではなく `cargo-topcoat dev`。topcoat-cli 0.5.0 は cargo
> サブコマンドとして呼ばれたときの引数を解釈できない。
>
> `cargo run` でも起動する。静的ファイルはバイナリに埋め込んであり、
> topcoat のアセットバンドルは使っていない。dev CLI を使う利点は自動リビルドだけ。

## 運用

- **バックアップはファイルコピーではなく `VACUUM INTO`。** WAL を使っているので、
  `fugantt.db` だけコピーしても不完全なことがある

  ```sh
  sqlite3 fugantt.db "VACUUM INTO '/backup/fugantt-$(date +%F).db'"
  ```

- **サーバーは1台まで。** SQLite をファイルで持つので、同じデータベースを2つのプロセスから
  書くと壊れる。負荷分散のつもりで増やさないこと
- **更新は EXE の差し替え。** 起動時にマイグレーションが自動で走る。**戻す手段は無い**ので、
  入れ替える前にバックアップを取ること
- **消えて困るものは JSON でも出しておく。** 画面から書き出せて、そのまま取り込める

## アカウント

ログイン名は**メールアドレスでなくてもよい**（`yamada` でも通る）。社内で配るときに、
読まれないアドレスを発明しなくて済む。登録時に入力した**名前**が画面と変更履歴に出る。

管理者は「全体の設定」で、左上のアプリ名と**元号の表**を変えられる。
元号は `2019-05-01 令和` のように1行ずつ書く形式で、次の元号が決まったら1行足すだけで済む
（発表から施行まで1か月ほどしかないので、コードに埋めると詰む）。

## JSON の形

書き出したファイルは、そのまま読んで、直して、戻せる。**AI に渡して考えさせて返す**、
という使い方を想定した形にしてある。

```json
{
  "version": 1,
  "name": "リリース計画",
  "settings": { "memo": "…" },
  "statuses": [{ "name": "実施中", "color": "#dbeafe", "percent": null }],
  "assignees": [{ "name": "山田", "color": "#1e3a8a", "background": "#dbeafe" }],
  "holidays": [{ "date": "2026-08-11", "name": "山の日" }],
  "leaves": [{ "assignee": "山田", "start": "2026-08-17", "end": "2026-08-21", "note": "夏季休暇", "kind": "off" }],
  "fields": [{ "label": "製品", "kind": "select", "options": [{ "value": "A", "color": "", "background": "" }] }],
  "tasks": [
    {
      "id": "c0ffee…", "name": "要件定義", "depth": 0,
      "start": "2026-08-03", "end": "2026-08-14",
      "actual_start": "2026-08-03", "actual_end": "2026-08-18",
      "progress": 100, "status": "完了", "assignee": "山田", "note": "",
      "waits": ["2026-08-17/2026-08-21"],
      "fields": { "製品": "A" }
    }
  ]
}
```

読むときに知っておけばいいのは、これだけ。

| | |
| --- | --- |
| `depth` | 0 から。1つ上の行より深ければ、その行の子。2段以上深い行は1段に戻す |
| `progress` | 0〜100 |
| `waits` | `"開始/終了"`。終わりを省いて `"開始/"` と書けば、まだ待っている |
| `id` | **あれば更新、無ければ追加。ファイルに無い行は削除**。手で書くなら省いてよい |
| 参照 | ステータスも担当者も独自項目も、**id ではなく名前**で書く |
| 集計行 | 子を持つ行の日付と進捗は書き出さない（子から決まるので、書いても矛盾するだけ） |

**日数・差異・遅延・期待進捗はファイルに入っていない。** 全部その場で計算する値なので、
書き戻すときに矛盾を作れない。逆に、それらを**読みたい**ときは
`GET /api/projects/{id}/grid` が計算済みの表をそのまま返す。

> 読むのは grid（計算済み）、書くのは JSON（入力だけ）。

`version` が今より新しいファイルは、半端に読まずに断る。

## API トークン

ブラウザの外から**1つのプロジェクトだけ**を読み書きするための鍵。設定 → API トークンで、
オーナーが発行する。**発行のときに一度だけ表示**して、保存するのはハッシュだけ。
権限は「読むだけ」と「読み書き」の2つ。

```sh
# 読む
curl -H "Authorization: Bearer fug_…" \
  https://example.com/api/projects/release-plan/document

# 直して書き戻す
curl -X POST -H "Authorization: Bearer fug_…" \
  -H "Content-Type: application/json" --data @plan.json \
  https://example.com/api/projects/release-plan/document
```

計算済みの表が欲しければ `GET /api/projects/{id}/grid`。日数・差異・遅延・期待進捗まで
入っている。

- 別のプロジェクトのトークンでは **403**
- 読むだけのトークンで書けば **403**
- 鍵もクッキーも無ければ **403**（ログイン画面に飛ばさない。JSON を待っている相手に
  ログインフォームを 200 で返しても仕方がない）
- トークンで書いた変更は、変更履歴に**人の名前が付かない**。誰もやっていない作業に
  名前を書かないため

## 安全に運用するために

外に置くなら、次の3つだけは確かめてから公開する。

1. **`FUGANTT_NO_AUTH` を設定しない。** 設定すると誰でも全プロジェクトを読み書きできる。合言葉を
   要求するうえ、`HOST` が外向きなら起動を拒否し、全ページに警告帯を出すが、それでも確認する
2. **`FUGANTT_ALLOW_HTTP` を設定しない。** セッションのクッキーから `Secure` が外れる
3. **ベース権限の意味を決めておく。** `編集者`/`閲覧者` は**全プロジェクトに効く**既定値で、
   部署ごとに秘密にしたい案件があるなら、ベースは `無効` にして必要なプロジェクトに招く

中身の作りは次のとおり。

- パスワードは **Argon2** のハッシュで保存する。生の値はどこにも残さないし、記録もしない
- セッションは 32 バイトの乱数トークン。データベースに入るのはその **SHA-256** だけで、
  クッキーは `__Host-` 接頭辞つき・`Secure`・`HttpOnly`・`SameSite=Lax`
- 変更はすべて POST。`SameSite=Lax` と合わせて、他所のページから勝手に叩かせる筋を塞いでいる
- SQL は例外なくプレースホルダ。画面の文字列はサーバー側でエスケープし、
  表の島は `innerHTML` を一度も使わない
- ログインの失敗は「ユーザー名かパスワードが違います」に統一（どちらが違うかを言わない）し、
  続けて失敗すると待たされる
- パスワードを変えると、**その人の他のセッションは切れる**（いま操作している画面は残る）

SQLite なので、置くのは**1台**。同じデータベースを2台で開くと、2つの別の計画になる。

## 全体とプロジェクトの境目

会社の事実は全体に、計画の事実はプロジェクトに置く。新しい計画を作るたびに祝日を貼り直す
仕組みは、貼り直されなかったほうが静かに間違うので採らない。

| 全体（管理者） | プロジェクト |
| --- | --- |
| 祝日・休業日 | この現場だけの休み／「全体は休みだがここは動く」日 |
| 担当者の色 | この計画に出てくる担当者の一覧 |
| 担当者の休暇・出社 | — |
| 既定のステータス（作成時に**写す**） | そのプロジェクトのステータス |
| アプリ名・元号 | 列・独自項目・ステータス・表示・メモ |

祝日は「全体の一覧 ＋ この計画で足した日 − この計画で外した日」。プロジェクトの設定には
どちらから来た日かが出て、全体の日は「この計画では働く」で外せる（戻すのも同じ画面）。

担当者の色を全体に置いたのは、同じ人が案件ごとに違う色だと、いくつも開いたときに読めなく
なるため。休暇は人につくものなので、どこか一つの計画に入れれば、その人の出ている全部の計画で
日数から外れる。

**登録は招待制。** 最初に登録した人が管理者になり、以降はその人が配った招待リンクからしか
登録できない。招待の管理は左のメニューの「招待」から。

- 招待リンクは1回使うと無効になる
- メールアドレスを指定すれば、その人しか使えない
- ログインの失敗が15分で8回を超えると、そのアドレス（とIP）は15分止まる。成功すれば数え直す。
  Argon2 は1回ずつが重いので、これは総当たり対策であると同時に過負荷対策でもある

接続元 IP は `Fly-Client-IP` / `X-Forwarded-For` から読む。プロキシがなければ
メールアドレスだけで数える。

### 認証なしで動かす

社内の閉じたネットワークでは、ログイン画面が守りより手間になることがある。

```sh
FUGANTT_NO_AUTH=yes-everyone-on-this-network-can-edit ./fugantt
```

**この URL に届く人は全員が全プロジェクトを読み書きできる。** 誰が変更したかも区別されない
（全員が同じ「共有アカウント」になる）。

わざと面倒にしてある。値が決まった文言でなければ**起動を拒否**し、`HOST` が
`127.0.0.1` 以外ならさらに `FUGANTT_NO_AUTH_I_MEAN_IT=1` も要求する。
動いている間は画面の上に帯が出続ける。

## 変更履歴

プロジェクトごとに、誰がいつ何を変えたかを残す。左のメニューの「変更履歴」から見られる。

変更前の値は**置き換わる瞬間にしか存在しない**ので、後から再構成はできない。
各変更と同時に書いている。削除されたタスクの履歴も読めるよう、タスク名は文字列で持つ。

## プロジェクトの URL

`/projects/リリース計画-2026` のように、**プロジェクト名がそのまま URL になる**。
UUID の羅列はリンクを貼られたときに何のことか分からない。

- 空白と記号は `-` に畳む。日本語はそのまま残す（ブラウザは復号して表示する）
- **同じ名前のプロジェクトは作れない。** URL が名前である以上、重複は成立しない
- 既存の UUID の ID もそのまま動く。ID は単なる文字列で、移行は要らない

## 操作

グリッドはキーボードで操作する。

| キー | 動作 |
| --- | --- |
| 矢印 | セル移動 |
| Tab / Shift+Tab | 前後のセルへ。行末で次の行の先頭へ回り込む |
| Enter | 編集を開く（F2 と同じ）。移動は ↓ で |
| ダブルクリック | 編集を開く |
| 文字入力 | その文字で編集開始（日本語変換を含む） |
| F2 | 既存の値を編集 |
| Esc | 編集を取消 |
| Enter / Tab（編集中） | 確定して下 / 右へ |
| Delete / Backspace | セルを空にする |
| ⌘/Ctrl+Enter | 選択行の下に行を追加 |
| ⌘/Ctrl+Delete | 選択行を削除（子タスクも一緒に消える） |
| Home / End | 行の先頭 / 末尾。⌘/Ctrl 併用で表の先頭 / 末尾 |
| ⌥/Alt+→ ← | 直前の行の子にする / 階層を戻す |
| ⌥/Alt+↑ ↓ | 兄弟の中で並べ替え |
| ⌘/Ctrl+← → | 折りたたむ / 展開する |

修飾キーは `⌘` と `Ctrl` のどちらでも効く。画面に出る表記だけが OS で変わる。
Windows では `Alt+←/→` がブラウザの「戻る／進む」に割り当てられているため、
このハンドラの `preventDefault` は整形ではなく機能上必要。

チャートには **開始差異**をバーの左に、**予実差異**を右に出す。どちらが遅れたのかは、
どちら側に数字が出るかで分かる。

表とチャートは別々に横スクロールする。見出しと絞り込みの行は列と一緒に横へ動き
（動かないと列の上に別の列の名前が出る）、タスク名の列だけが左に固定される。

バーはドラッグで期間ごと移動、左右の端（7px）をつまむと開始日・終了日だけ伸縮する。
**実施バーも同じように動かせる。** ただし進行中（実施終了が空）の行は、動かしても終了日を作らない
— 右端をつまんだときだけ終了日を書く。横に押しただけで「終わったこと」にはしない。
日単位でスナップし、離したときに 1 回だけ確定を送る。開始と終了は同時に書き換えるので、
「終了が開始より前」という状態を経由しない。

右クリックで同じ操作のメニューが出る。⌥ 系は名前が付いていないと気づけないため。

画面の操作（設定・書き出し・取り込み・プロジェクト一覧・ログアウト）は左のドロワーにまとめてある。
チェックボックスと CSS だけで開閉するので、グリッド島の JavaScript とは独立に動く。

選択中のセルには**常に透明な入力欄**が置かれ、そこにフォーカスがある。
IME は `div` に対して変換を開始できないので、これが無いと日本語がまったく入力できない。
打ち始めるとその入力欄が**そのまま**編集欄になる。要素を作り直すと変換中の文字が消えるため。

折りたたみ状態は **localStorage にプロジェクト単位で持つ**。どこを畳んで読んでいるかは
その人のその時の見方であって、プロジェクトのデータではない。サーバーに置くと他のメンバーの
画面まで畳まれてしまう。畳んだ行には隠している件数（`+2`）が出る。集計行のバーは畳んでも残る。

畳んだ親の中へ行を移動すると自動で開く。移動した行が消えて見えなくなるため。

`⌥→` は**同じ階層で1つ上にある行**の子にする。画面上の1つ上の行ではない。
その階層の先頭にいる行は親にする相手がいないので動かない。

動かせないときは理由を出す（「同じ階層で1つ上の行がないため、子タスクにできません。」など）。
当初はアウトライナに倣って黙って空振りさせていたが、
「何も起きない」と「壊れている」が区別できず、実際に迷わせたので改めた。

行の左端のつまみをドラッグすると、行を上下に動かせる。落とす位置の線が階層を示し、
横方向のドラッグ量で階層が決まる。自分の子孫の中には落とせない。

表とチャートの間の境界をドラッグすると、幅を変えられる。幅は localStorage に残る。

**縦スクロールはグリッドの中で起きる。ページ自体は動かない。**
そうしないと見出しを `sticky` で止められない。左右のペインはそれぞれ独立にスクロールし
（各々が sticky の基準になる必要があるため）、縦位置だけを島が同期させている。

左右の見出しは同じ高さになるよう CSS 変数で揃えてある。片側にだけ枠線があると、
すべての行とバーが 1px ずつずれる。

絞り込みは**列ごと**に、見出しの上の行で行う。複数の列を埋めれば AND で効く。
一致した行の親は、階層が読めなくならないよう残す。0 件になっても絞り込み行は消えない
（消えると元に戻せなくなる）。

日付・数値の欄は**全角のままでも通る**。日本語入力を切り替えずに `２０２６－０９－０１` と
打っても同じ日付として読む。クライアントとサーバーの両方で正規化している。

バーの中ほど、完了分と予定分の境目もつまんで動かせる。進捗が変わる。

**進捗の塗りは予定バーに乗る**。実施バーが持つのは「いつ動いていたか」だけで、塗りはない。
一つの値を二本のものさしで測らないための決まりで、実施バーに乗せると、同じ 60% が行ごとに
別の位置に出るうえ、終わっていない実施バーは今日まで伸びるので、何もしていない日でも塗りが
進んで見えてしまう。今日までに終わっているはずの分に届いていなければ、塗りの右隣に**遅れの帯**が出る。

集計行（子を持つ行）の日付・日数・進捗は子から決まるため編集できない。斜線で示していて、
サーバー側でも 403 で拒否する。斜線は「子から決まる」の意味に限る。日数のように常に導出の列は
薄い文字だけで示す。

列は タスク名 / 開始 / 終了 / 日数 / 進捗 / ステータス / 担当者 / コメント。
ステータスは 未着手・実施中・完了・保留 から選ぶ。進捗とは連動させていない
（「実施中 0%」も「完了 100%」も計画が言いうることなので、片方から片方を決めると入力を上書きする）。

## Windows

修飾キーは `⌘` と `Ctrl` のどちらでも受け付ける。画面の表記だけが OS で切り替わる。
グリッドのフォントは Windows の日本語フェイス（Yu Gothic UI / Meiryo）まで明示している。

`Alt+←/→` は Windows のブラウザで「戻る／進む」に割り当てられているため、
キーハンドラの `preventDefault` はここで機能上の意味を持つ。

## 共同編集

同じプロジェクトを開いている全員に、変更が SSE で伝わる。流れるのはリビジョン番号だけで、
受け取った側は取り直す。他人の編集をそのまま適用しないので、順序が狂うことがない。

自分の変更は無視する。サーバーはレスポンスを返す前に配信するため、リビジョンの比較だけでは
自分のエコーと他人の編集を区別できない。ブラウザごとの ID を `X-Fugantt-Client` で送り、
戻ってきた同じ ID を捨てている。

編集中は取り込まない。入力途中の内容を捨てないため。

## 権限

| 権限 | できること |
| --- | --- |
| 管理者 | すべて。メンバーの追加・変更・削除 |
| 編集者 | タスクと設定の変更 |
| 閲覧者 | 読むだけ |

サーバー側で拒否する。画面から編集 UI を消すのは親切のためで、防御ではない。
最後の管理者は自分を外せない。

## 予定と実施

日付は **予定開始・予定終了・実施開始・実施終了** の4つを1行に並べる。
その右の **開始差異**（実施開始 − 予定開始）と **予実差異**（実施終了 − 予定終了）は
保存しない。予定と実施から毎回引く。

チャートでは予定を破線の枠、実施をその中の実線で描く。差が **形** で出るので、
比べるための2行目がいらない。**開始差異はバーの左、予実差異は右**に出る。

実施バーもドラッグで動かせる。ただし進行中（実施終了が空）の行は、動かしても終了日を作らない
— 右端をつまんだときだけ終了日を書く。

## 進捗

既定は手入力。**自動計算はしない** — 進捗は期待進捗（暦から計算）と比べて遅延を判定しているので、
進捗まで暦から出すと `進捗 == 期待進捗` になり、遅延が永久に立たなくなる。
進捗は計画から独立した観測値であることに意味がある。

代わりに、**二重入力になっている事実だけ**を埋める。

| 設定 | 動き |
| --- | --- |
| 手入力（既定） | 何もしない |
| ステータスに連動 | その状態に設定した進捗を入れる（既定は `完了` → 100% / `未着手` → 0%）。進捗を空にした状態は手入力のまま |

設定に関わらず、**進捗を 100% にすると実施終了が空なら今日の日付が入る**。
すでに入っている日付は書き換えない。集計行は子から決まるので、どちらも書き込まない。
連動で書いた分も変更履歴に残る。

## 担当者

担当者はプロジェクトのメンバー（アカウントの**表示名**）からの選択式。
一覧には、すでにタスクに入っている名前も残るので、これまでの割り当ては消えない。
「全体の設定」の「担当者の色」で**文字色と背景色**をつけると、担当者の列が色分けされる
（色は全プロジェクト共通）。
ここに名前を足せば、**アカウントの無い人**（協力会社・他部署）も選べる。
アカウントは登録時に名前を入力する。画面に出るのはメールアドレスではなくその名前で、
変更履歴の「誰が」も名前になる。

## 列

設定の「列」で、組み込み列も独自項目も**まとめて**扱う。

- **表示** — タスク名以外は外せる
- **幅** — px で指定、空欄なら列の種類ごとの既定
- **並び順** — ↑↓ で入れ替え。タスク名は先頭で固定

並び順は**保存された分だけ**を見る。あとから増えた列は、設定を触っていなくても末尾に出る。
Excel の書き出しも同じ順に従う。

## 絞り込み

見出しの上の行に1列1つ。複数埋めれば AND。日付・日数・差異・進捗は**大小比較**で、
欄の左のボタンから **以上・以下・一致・超過・未満**を選ぶ（既定は `予定開始` が以上、
`予定終了` が以下）。`100以下` `>=3` のように打ち込んでも同じ。

進捗にはもう二つ、**遅れ**と**順調**がある。今日までに終わっているはずの分と比べるだけなので
打ち込む数字がなく、「遅れている行だけ見せて」がボタン二つで済む。判定はチャートの赤い帯と同じ。

絞り込み中はヘッダーに残り行数と「解除」が出る。「解除」は選んだ比べ方も既定に戻す。

## 担当者の休暇

スケジュール画面の「担当者の休暇/出社」ボタンから、担当者名と期間を入れる（設定ではなく
通常業務なので、設定画面ではなく作業する画面にある）。担当者名は 担当者 列の文字列で照合する
（アカウントとは結びつけない。協力会社や他部署の人も計画には出てくる）。

休暇は**人につく**ので、登録はその人が出ている全部の計画に効く。「休みだけど出社」も同じ
ダイアログで入れられて、こちらは土日祝でもその日を数える。

その人が休んでいる日は、**その人のタスクの日数に数えない**。遅延の判定も同じ暦を使うので、
休んでいる間に「進んでいない」と言われることはない。チャートでは**その人の行だけ**が休暇の色で塗られる（色は設定で変えられる）。
セルにマウスを乗せると誰が休みかが出る。

「日数から土日祝を除く」設定とは独立して効く。休暇は人ごとに入れたものなので、
暦日で数えるプロジェクトでも無視しない。

## 統計

ドロワーの「統計」に、そのプロジェクトの数字が出る。

- タスク数・平均進捗・遅延中の数・遅れ日数
- ステータス別の件数、担当者別の件数と平均進捗

数えるのは葉のタスクだけ。集計行は子の合計なので、足すと二重になる。
終わったタスクは予実差異が遅れ、終わっていないタスクは**今日が予定終了をどれだけ過ぎたか**が遅れ。
月曜の朝に見たい数字は後者を含む。

## 設定

プロジェクトごとに設定する。

| 項目 | 内容 |
| --- | --- |
| 祝日・休業日 | 全体の暦との差分。この現場だけの休みを足し、全体の休みを「この計画では働く」で外す。日本の祝日の一括登録は「全体の設定」（振替休日・国民の休日まで計算する） |
| 日数から除く日 | 土曜・日曜・祝日・担当者の休暇を**個別に**選ぶ。**既定は土日祝と休暇を除く**（月〜金も個別に外せる） |
| 固定する列 | 横スクロールしても左に残す列数（既定はタスク名だけ） |
| 列 | 表示・幅（px）・並び順。組み込み列と独自項目をまとめて扱う（タスク名は先頭で固定） |
| 年度の開始月 | 四半期の区切り。日本の年度はたいてい4月 |
| 和暦 | 年の表記を令和にする |
| 1日の幅 | チャートの目盛り（12〜36px） |
| ステータス | 名前・色・その状態が意味する進捗（空なら手入力のまま）。新しいプロジェクトは「全体の設定」の既定を**写して**始まる |
| 独自の項目 | フリー・選択・フリー＋選択・日付・数値。**名前はあとから直せる**（入力済みの値はそのまま）。種類を変えられるのは、その列がまだ空のときだけ。選択肢は項目を作ったあとに、その場で追加・並べ替え・文字色/背景色を指定する |
| 色 | 予定・完了分・集計行・遅延・**土曜**・**日曜**・祝日・**休暇** |
| 進捗の入れ方 | 手入力／ステータスに連動 |
| 担当者 | この計画に出てくる名前。色は「全体の設定」で全員共通に決める |
| メンバー | 管理者・編集者・閲覧者 |

「プロジェクトメモ」はヘッダーの「メモ」から右側のパネルで開く。**プレーンテキスト**。
改行はそのまま出る。記号は記号のまま出る（他のメンバーの画面に出るものなので、
書式として解釈せず、文字として表示する）。

設定のチェックボックスは `column_status` のように1つずつ別の名前で送る。
url-encoded の本文は同名キーの繰り返しを配列にできない。

**日数から土日祝を除く設定は、遅延判定にも効く。** 日曜に進まない前提のタスクを
「日曜に進まなかった」ことで遅延扱いにはできない。

## 日本の環境向け

- **祝日は計算で出す。** `src/holidays.rs` が国民の祝日法の規則を実装している。
  固定日・ハッピーマンデー・春分秋分の近似式に加え、**振替休日**と**国民の休日**まで。
  2020年以降が対象（天皇誕生日の移動とスポーツの日への改称のため）
- **日付の下に曜日を出す。** 月末から金曜を数えるのは計画ではない
- **土曜は青、日曜と祝日は赤。** 日本のカレンダーの慣行に合わせてある。
  同じ灰色にすると読み違える
- **日付・数値は全角のままでも通る。** 日本語入力を切り替えなくてよい
- **年度と四半期をチャートの上に出す。** 開始月は設定で変える（既定は4月）
- **和暦。** 設定を入れると `令和8年度 Q2` のように出る
- グリッドのフォントは Windows の日本語フェイスまで明示している

独自項目の値は `task_field_values` に縦持ちする。列を足すたびに `ALTER TABLE` はしない。
色は `#rrggbb` 以外を保存しない。スタイルシートに直接入る値なので、
エスケープして祈るのではなく形式を限る。

## 書き出しと取り込み

プロジェクト画面から Excel（`.xlsx`）と **JSON** を書き出せる。
JSON は取り込みもできる（**全置換**：ファイルが計画そのもの）。
階層は `depth` で持つので、手で書いても括弧を数えずに済む。
集計行の日付と進捗は書き出さない（子から決まる値なので、書くとファイルが自分と矛盾する）。

Excel は
**画面と同じ列**（隠した列は隠したまま、独自項目も含む）を左に、日ごとのセルでチャートを右に置く。
予定は薄い塗り、実施はその上の濃い塗り、休暇は灰色の斜線。

## グリッド島

`web/` が唯一の TypeScript。ビルド結果 `web/dist/` は **コミットする**。
Rust 側は `asset!` でそれを埋め込むので、サーバーのビルドに Node は要らない。

```sh
cd web
npm install
npm run build      # dist/grid.js と dist/grid.css を作る
npm run watch      # 編集しながら
npm run typecheck
```

グリッドを直したら `npm run build` を忘れないこと。
Rust 側は `dist/` の中身を `include_str!` でビルド時に取り込む。

| `src/api.rs` | グリッド島が叩く JSON |
| `src/domain.rs` | 親タスクの集計と遅延判定。導出値の唯一の実装 |

## テスト

```sh
cargo test
cd web && npm run typecheck
```

グリッドはキーボード操作とサーバーへの往復が本体なので、ブラウザで動かして確かめる。
dev サーバーを起動したまま、それが使っている DB を渡す。

```sh
cd web
FUGANTT_DB=../fugantt.db npm test
```

`test/seed.sh` が `test-project` を毎回作り直すので、何度走らせても同じ結果になる。
Chrome の場所は `CHROME`、URL は `FUGANTT_URL` で変えられる。

> ソースを触った直後にテストを走らせないこと。`cargo-topcoat dev` のファイル監視が
> 再ビルドでサーバーを落とし、テストの途中で接続が切れる。
