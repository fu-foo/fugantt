# fugantt

**予定と実績を並べて、営業日で数えるガントチャート。**
Excel のキーボード操作のまま編集できる。サーバーは Rust（Topcoat + SQLite）、EXE 1本で動く。

[English](README.en.md)

![スケジュール画面](docs/images/schedule.png)

## できること

- **予定と実施を1行で持つ。** 開始差異・終了差異は保存せず、毎回引き算で出す
- **遅れを分けて見せる。** 「12日遅れ」ではなく「作業9日＋待ち3日」
- **日数はその現場の数え方で。** 土日・祝日・個人の休暇・待ちを除く（既定は除く）
- **日本の暦がはじめから正しい。** 祝日は計算（振替休日・国民の休日まで）、年度、和暦、土曜は青・日曜は赤
- **キーボードで編集する。** 矢印・Enter・Tab。日本語入力もそのまま通る
- **Excel と JSON に書き出せる。** JSON は取り込みもできる
- **既定は日本語、読む人のブラウザが英語なら英語**

## 動かす

```sh
cargo-topcoat dev                     # 開発。http://127.0.0.1:3000
cargo build --release                 # 配布用の EXE 1本
```

| 環境変数 | 既定 | |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | `0.0.0.0` で LAN に公開 |
| `PORT` | `3000` | |
| `FUGANTT_DB` | `fugantt.db` | SQLite ファイル。起動時に自動でマイグレーション |
| `FUGANTT_ALLOW_HTTP` | — | `1` で平文 HTTP を許可（後述） |

Docker と Fly.io の設定も入っている（`Dockerfile` / `fly.toml`）。
ビルド済みのバイナリは [Releases](https://github.com/fu-foo/fugantt/releases) から。

> `cargo topcoat dev` ではなく `cargo-topcoat dev`。topcoat-cli 0.5.0 は
> cargo サブコマンドとして呼ばれると引数を解釈できない。`cargo run` でも動く。

### 社内 LAN に置くとき

セッションクッキーは既定で `Secure` + `__Host-` が付く。**ブラウザは localhost 以外の
`http://` から `Secure` クッキーを受け取らない**ので、そのままでは LAN の IP でログインできない。
`FUGANTT_ALLOW_HTTP=1` を立てると `Secure` を外す（トークンが平文で流れる。起動時に警告が出る）。

HTTPS を用意できるならそちらが正しい。Caddy の `tls internal` か Tailscale の証明書が手軽。

### 運用

- **バックアップは `VACUUM INTO`。** WAL があるのでファイルコピーでは不完全になる
  ```sh
  sqlite3 fugantt.db "VACUUM INTO '/backup/fugantt-$(date +%F).db'"
  ```

- **更新は EXE の差し替え。** マイグレーションは自動、**戻す手段は無い**。先にバックアップを

## 操作

| キー | 動作 |
| --- | --- |
| 矢印 | セル移動 |
| Tab / Shift+Tab | 前後のセルへ。行末で次の行へ回り込む |
| Enter / F2 / ダブルクリック | 編集を開く |
| 文字入力 | その文字で編集開始（日本語変換を含む） |
| Esc | 編集を取消 |
| Enter / Tab（編集中） | 確定して下 / 右へ |
| Delete / Backspace | セルを空にする |
| ⌘Enter / Ctrl+Enter | 選択行の下に行を追加 |
| ⌘Delete / Ctrl+Delete | 選択行を削除（子タスクも消える） |
| Home / End | 行の先頭 / 末尾。⌘ / Ctrl 併用で表の先頭 / 末尾 |
| ⌥→ ← / Alt+→ ← | 直前の行の子にする / 階層を戻す |
| ⌥↑ ↓ / Alt+↑ ↓ | 兄弟の中で並べ替え |
| ⌘← → / Ctrl+← → | 折りたたむ / 展開する |

修飾キーは `⌘` と `Ctrl` のどちらでも効く。**画面に出る表記だけが OS で変わる。**
右クリックで同じ操作のメニューが出る。

バーはドラッグで移動、端（7px）をつまむと開始日・終了日だけ伸縮する。実施バーも同じ。
ただし進行中（実施終了が空）の行は、押しただけでは終了日を作らない。
予定バーの中のつまみで進捗が変わる。

日付は `20260805` `8/5` `2026-08-05` のどれでも通る。全角のままでもよい。

## 予定と実施

日付は **予定開始・予定終了・実施開始・実施終了** の4つ。その右の **開始差異**と**終了差異**は
保存せず、毎回引く。チャートは予定が枠、実施がその下の実線。

- **進捗の塗りは予定バーに乗る。** 実施バーに乗せると同じ 60% が行ごとに別の位置に出るうえ、
  終わっていない実施バーは今日まで伸びるので、何もしない日でも塗りが進んで見える
- **遅れは帯で出る。** 今日までに終わっているはずの分に塗りが届いていなければ、その差が赤く出る
- **待ち**（他部署待ちなど）は期間と理由で登録する。その日数は日数からも遅延判定からも外れる
- **担当者の休暇/出社**はスケジュール画面のボタンから。休暇は**人につく**ので、
  その人が出ている全部のプロジェクトに効く

進捗は**自動計算しない**。期待進捗（暦から計算）と比べて遅延を判定しているので、
進捗まで暦から出すと遅延が永久に立たなくなる。
設定で「ステータスに連動」を選ぶと、その状態に決めた進捗が入る。
どちらの設定でも、**100% にすると実施終了が空なら今日が入る**。

## 絞り込み

見出しの上の行に1列1つ。複数埋めれば AND。日付・数値は欄の左のボタンから
**以上・以下・一致・超過・未満**を選ぶ（`100以下` `>=3` と打っても同じ）。
進捗にはもう二つ、**遅れ**と**順調**がある。打ち込む数字がないので、ボタン二つで済む。

## 設定

会社の事実は**全体**に、計画の事実は**プロジェクト**に置く。

| 全体（管理者） | プロジェクト |
| --- | --- |
| 祝日・休業日 | この現場だけの休み／「全体は休みだがここは動く」日 |
| 担当者の色 | この計画に出てくる担当者 |
| 担当者の休暇・出社 | 列・独自項目・表示・メモ・メンバー |
| 既定のステータス（作成時に**写す**） | そのプロジェクトのステータス |
| パスワードの決まり・アプリ名・元号・言語 | |

祝日は「全体 ＋ この計画で足した日 − この計画で外した日」。
ステータスを写しにしているのは、参照にすると全体を直した瞬間に他人のチャートの色と
（連動していれば）進捗の数字が動くため。

プロジェクトの設定で触れるもの：

| 項目 | |
| --- | --- |
| 表示 | 日数から除く日（土日祝・休暇・曜日ごと）、年度の開始月、和暦、四半期、1日の幅 |
| 列 | 表示・幅（px）・並び順。組み込み列と独自項目をまとめて。タスク名は先頭で固定 |
| ステータス | 名前・色・その状態が意味する進捗（空なら手入力のまま）・並び順 |
| 独自の項目 | フリー・選択・フリー＋選択・日付・数値。**名前はあとから直せる**（値はそのまま）。種類を変えられるのはその列が空のときだけ |
| 色 | 予定・完了分・実施・集計行・遅延・土曜・日曜・祝日・休暇・待ち |
| メンバー | オーナー・編集者・閲覧者 |

## 書き出しと取り込み

Excel（`.xlsx`）は読むため、JSON は動かすため。JSON はプロジェクト全部——設定・名簿・暦・タスク——
が1つのファイルに入る。

```json
{
  "version": 1,
  "name": "リリース計画",
  "tasks": [
    { "id": "c0ffee…", "name": "要件定義", "depth": 0,
      "start": "2026-08-03", "end": "2026-08-14",
      "actual_start": "2026-08-03", "actual_end": "2026-08-18",
      "progress": 100, "status": "完了", "assignee": "山田",
      "waits": ["2026-08-17/2026-08-21"], "fields": { "製品": "A" } }
  ]
}
```

| | |
| --- | --- |
| `depth` | 0 から。1つ上の行より深ければその子 |
| `waits` | `開始/終了`。終わりを省けば、まだ待っている |
| `id` | **あれば更新、無ければ追加、ファイルに無い行は削除。** 手で書くなら省いてよい |
| 参照 | ステータスも担当者も独自項目も、id ではなく**名前** |
| 集計行 | 子から決まるので日付と進捗は書き出さない |

**日数・差異・遅延はファイルに入っていない。** その場で計算する値なので、書き戻して矛盾を作れない。
逆に読みたいときは `GET /api/projects/{id}/grid` が計算済みで返す。

> 読むのは grid、書くのは JSON。

## API トークン

設定 → API トークンで、オーナーが発行する。**1つのプロジェクトだけ**を開ける鍵で、
発行時に一度だけ表示される（保存するのはハッシュ）。権限は「読むだけ」「読み書き」。

```sh
curl -H "Authorization: Bearer fug_…" \
  https://example.com/api/projects/release-plan/document          # 読む

curl -X POST -H "Authorization: Bearer fug_…" \
  -H "Content-Type: application/json" --data @plan.json \
  https://example.com/api/projects/release-plan/document          # 書き戻す
```

他のプロジェクトの鍵、読むだけの鍵での書き込み、鍵もクッキーも無い要求はすべて **403**。
トークンで書いた変更には、変更履歴に人の名前が付かない。

## 安全に運用するために

- パスワードは **Argon2** のハッシュ。生の値はどこにも残さない
- セッションは32バイトの乱数で、DB に入るのは **SHA-256** だけ。クッキーは
  `__Host-` + `Secure` + `HttpOnly` + `SameSite=Lax`
- 変更はすべて POST。SQL は例外なくプレースホルダ。島は `innerHTML` を使わない
- パスワードを変えると、その人の他のセッションは切れる
- パスワードの決まり（最低文字数・必要な文字種・使わせない語）は全体の設定で決める
- **ベース権限の「編集者」「閲覧者」は全プロジェクトに効く。** 案件を分けたいなら
  ベースは「無効」にして、必要なプロジェクトに招く

`FUGANTT_NO_AUTH=yes-everyone-on-this-network-can-edit` で認証なしにもできる。
**この URL に届く人は全員が全プロジェクトを読み書きできる。** 起動を拒む条件を重ねてあり、
動いている間は画面の上に帯が出続ける。信頼できるネットワークだけで。

## 構成

- `src/domain.rs` が派生値を全部持つ。日数・差異・期待進捗・集計。ブラウザは描くだけ
- グリッドだけがブラウザ側の TypeScript（島）。ほかはサーバーが HTML を返す
- 変更は SSE で他の画面へ届く
- テストは `cargo test`（ドメイン）と、実際の Chrome を動かすブラウザ側の一式
  （`web/test/grid.test.mjs`）。「要素がある」はテストではなく、computed style と幾何がテスト
