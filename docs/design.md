## 派生値は保存しない

開始差異・終了差異・日数・遅れは保存せず、毎回計算する。JSON にも入れない。
書き戻したファイルが自分自身と矛盾することがない。

## 納期と予定は違う問いに答える

納期と予定は競合する終了日ではない。どの数字をどちらで測るかは一度だけ決めてある。

| 数字 | ものさし |
| --- | --- |
| 納期に間に合うか | 納期だけ |
| 段取りから遅れているか | 予定進捗と予定終了 |
| 稼働・空き検索の日数 | 予定バーだけ。納期しかない行は0日 |

「この日までにやればOK」のタスクに期間を置かないのは、置いた瞬間にその人の稼働を食うから。

集計行の納期は子の最大だが、遅れは子から吸い上げる。親の納期から計算し直すと、
10/5 の約束を落とした子が、親の 11/30 が来るまで見えない。

## 進捗は自動計算しない

暦から進捗を出すと、日が経てば進捗も進むので、遅れが立たなくなる。
だから進捗は入れるもの（ステータスに連動か、手入力）。

## 予定進捗

**点と点の間は判定しない。** 8/20 に 30%、8/28 に 100% と入れたなら、見るのはその2日だけ。
間を直線で結ぶのは、誰も立てていない計画を発明することになる。

**帯の端はバーの 50% の位置で、日付の位置ではない。** このバーは掴むと進捗を入れる装置なので、
横軸は％として読まれる。比べるもの同士を同じものさしに乗せる。

**入れなければ何も言わない。** 遅れは日数から割り出すものではなく、立てた予定に対して出る。
線を引きたいだけなら入れなくていい。期限超過（予定終了を過ぎて実施終了が空）は日付の事実なので、
予定進捗が無くても赤くなる。

## 遅れ

**遅れは色ではなく列。** 「遅れている行だけ見せて」は、色では答えられない。

**2列に分けるのは、ものさしが違うから。** 1列に畳むと「納期に間に合わないもの」と
「段取りから遅れているもの」のどちらか一方しか引けない。
何も約束していない行は、何も破っていない（納期が無ければ納期遅れは空）。

**終わった遅れは赤くしない。** 遅れたことは記録として残るが、もう手の打ちようがない。
赤は、いま手を打てる行のためのもの。統計の「遅延中」と `/api/summary` の `delayed` も、いま遅れている行だけを数える。

**待ちは遅れから外す。** 止まっている日は作業の遅れではないし、その人が他のことに使える日でもある。
統計で「作業の遅れ」と「待ち」を分けて出すのは、他チーム待ちで遅れた計画と、作業が延びた計画とでは、
する話が違うから。

## 空き検索

- **今日から先を数える。** 半分過ぎた月で「空き12日」と言われても、その中には誰も使えない日が混ざっている。
  だから過ぎた日は「経過済」に分け、稼働可能日数 ＝ 経過済 ＋ 割当済 ＋ 空き日数 と足して合うようにしてある
- **1日は1日。** 同じ日に3件を3日と数えると、300% のような数字になって誰も読まなくなる。何重かは「重複」に別立てで出す
- **日付も出す。** 「9日空いている」は答えの半分
- **未割当も出す。** 誰も持っていない仕事が見えないと計画にならない
- **全体の空き検索がある。** 3案件持っている人は、プロジェクトごとのページではどれを見ても3倍空いて見える。
  そこで足し算をするのは人の仕事ではない。プロジェクトごとの暦の違いは、ほかの案件を代弁しないので使わない
- **工数の％は持たない。** 1日より細かくするには全タスクに数字が要り、それは誰も更新しない

## 表の編集

- **キーボードが先。** 今どこかの表に計画を打っている人は、マウスに手を伸ばさずに打っている。それより遅いものは1週間で使われなくなる
- **Enter で選択肢と日付は右へ進む。** 行に沿って埋める列だから
- **日付を来月へ送らない。** 実施開始に入れるのはたいてい過去の日。勝手に来月へ送ると「昨日」が打てなくなる
- **取り消しは他人の変更を消さない。** 他の人が触ったセルで止まるのは、そのため。
  削除を戻せないのは、消えた行を id ごと子孫ごと戻すのが別の話だから
- **行の色**は、★ や【重要】をタスク名に書いていた人のため。名前に書くと並べ替えにも書き出しにも残り続ける
- **集計行のバーを既定で出さない。** 子が開いていれば、子のバーが同じ期間を言っている
- **マウスオーバーに出す項目を選べる。** チャートの上で確かめられるなら、その列を出しっぱなしにしなくていい
- **新しい計画は11列で始まる。** 日数・差異・待ち・予定進捗は、チャートに出るかダイアログで入れるもの

## 全体とプロジェクト

会社の事実（祝日、人の色、休暇）は全体に、計画の事実（列、ステータス、その現場の休み）はプロジェクトに置く。

- **ステータスは写し。** 全体を直したときに、動いている計画の意味が勝手に変わらないように
- **休暇は全社で1つ。** その人が出てくるどの計画の編集者からも変えられる。担当者は自由に書ける名前なので、
  権限では区切らず、記録で追えるようにしてある
- **計画の色はプロジェクトのもの。** 外観の設定で変わらないのは、同じ計画を見ている二人が違う色で読んでいたら、話が合わなくなるから

## 日本の暦

- **祝日は貼り付けではなく計算。** 振替休日と、2つの祝日に挟まれた国民の休日まで。去年・今年・来年の分を自分で足す。
  一度入れた年は二度と足さないので、消した祝日は消えたまま
- **年度は月の上に出る。** 開始月は設定（既定は4月）
- **土曜は青、日曜は赤。** 同じ灰色の週末は読み違える
- **日付の下に曜日を出す。** 月のマス目から金曜を数えるのは計画ではない
- **和暦はデータ。** 新しい元号は設定に1行足すだけで、作り直しは要らない

どれも国に固定してはいない。祝日・年度・除く曜日・言語は、すべて設定。

## 配り方

- **ポートは 1861。** ヘンリー・ガントの生年
- **Docker イメージは amd64 だけ。** CI で QEMU 越しに Rust のリリースビルドを回すと、リリースを切るのが億劫になる時間がかかる
- **Windows の署名は買わない。** 初回の警告は「詳細情報」→「実行」で進む
- **認証は前段のプロキシに任せる。** LDAP・SAML・OIDC の難しいところは、すでに解いてあるところで解く
- **`--make-admin` は新しい権限を渡さない。** データベースのファイルに触れる人は、すでに全部を読める
