## キー操作

| キー | |
| --- | --- |
| 矢印 | セル移動 |
| Tab / Shift+Tab | 前後のセルへ。行末で次の行へ回り込む。計算で決まる列（日数・差異）は飛ばす |
| Enter / F2 / ダブルクリック | 編集を開く |
| 文字入力 | その文字で編集開始（日本語変換を含む） |
| Esc | 編集を取消 |
| Enter（編集中） | 確定して下へ。選択肢と日付は右へ |
| Tab（編集中） | 確定して右へ |
| Delete / Backspace | セルを空にする |
| ⌘Enter / Ctrl+Enter | 下に行を追加して、そのまま名前を打てる |
| ⌘Delete / Ctrl+Delete | 行を削除（子タスクも消える） |
| Home / End | 行の先頭 / 末尾。⌘ / Ctrl 併用で表の先頭 / 末尾 |
| ⌥→ ← / Alt+→ ← | 子にする / 階層を戻す |
| ⌥↑ ↓ / Alt+↑ ↓ | 兄弟の中で並べ替え |
| ⌘← → / Ctrl+← → | 折りたたむ / 展開する |
| ⌘Z / Ctrl+Z | 直前の変更を取り消す |
| ⌘Y / ⌘⇧Z / Ctrl+Y | やり直す |

`⌘` と `Ctrl` はどちらでも効く。OS で変わるのは画面の表記だけ。右クリックで同じ操作のメニューが出る。

## 設定項目

環境変数か、同じ名前を書いた `fugantt.ini`。環境変数のほうが強い。

`fugantt.ini` を探す場所は、実行ファイルの隣・カレント・利用者ごとの場所
（Windows は `%LOCALAPPDATA%\fugantt`、macOS は `~/Library/Application Support/fugantt`、
Linux は `~/.local/share/fugantt`）。`fugantt.conf` と `.env` も読む。

| 名前 | 既定 | |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | `0.0.0.0` で LAN に公開 |
| `PORT` | `1861` | |
| `FUGANTT_DB` | 下記 | SQLite ファイル。起動時に自動でマイグレーション |
| `FUGANTT_OPEN` | 自動 | `window`（アプリウィンドウ）／`tab`／`0`（開かない） |
| `FUGANTT_ALLOW_HTTP` | — | `1` で `Secure` クッキーを外し、平文 HTTP でもログインできる |
| `FUGANTT_NO_AUTH` | — | [認証なしで動かす](#認証なしで動かす) |

**`FUGANTT_OPEN` を書かないとき**: `127.0.0.1`・`localhost`・`::1` で立てたときだけ開く。
Windows は Edge のアプリウィンドウ（アドレスバー無し）、ほかは既定のブラウザのタブ。`0.0.0.0` なら開かない。

**DB の場所**: `FUGANTT_DB` →（カレントに `fugantt.db` があればそれ）→ 利用者ごとの場所、の順。
起動時に絶対パスを1行出す。すでに `fugantt.db` を置いて使っているなら、実行ファイルを差し替えても場所は動かない。

## コマンド

| | |
| --- | --- |
| `fugantt` | 前面で起動。閉じるか Ctrl+C で止まる |
| `fugantt start` | 裏で起動して、すぐ戻る（画面はいつもどおり開く） |
| `fugantt status` | 動いているか、URL・データ・ログの場所 |
| `fugantt log` | ログの最後 |
| `fugantt stop` | 止める |
| `fugantt --config` | どの値がどこから来ているか |
| `fugantt --help` | 書ける設定項目 |
| `fugantt --make-admin <ユーザー名>` | そのアカウントを管理者にする |

裏で動かすときのログとプロセス番号は、データの既定の場所に、ポートの番号つきで置く（`fugantt-1861.log`）。

## JSON の形

```json
{
  "version": 1,
  "name": "リリース計画",
  "tasks": [
    { "id": "c0ffee…", "name": "要件定義", "depth": 0,
      "start": "2026-08-03", "end": "2026-08-14", "due": "2026-08-20",
      "actual_start": "2026-08-03", "actual_end": "2026-08-18",
      "progress": 100, "status": "完了", "assignee": "山田",
      "waits": ["2026-08-17/2026-08-21"], "targets": ["2026-08-10/50"],
      "fields": { "製品": "A" } }
  ]
}
```

| | |
| --- | --- |
| `id` | 行を見分ける。このプロジェクトにある `id` ならその行を書き換え、無い・知らない `id` なら新しい行。**ファイルに無い行は消える**（下の注意） |
| `depth` | 0 から。1つ上の行より深ければその子 |
| `start` `end` `due` | 予定開始・予定終了・納期。`YYYY-MM-DD` |
| `waits` | `開始/終了`。終わりを省けば、まだ待っている |
| `targets` | `日付/％`。予定進捗 |
| 参照 | ステータスも担当者も独自項目も、id ではなく名前 |
| 集計行 | 子から決まるので日付と進捗は書き出さない |

> [!WARNING]
> 取り込みは**タスクの全置換**。`id` を省いたファイルを今あるプロジェクトに取り込むと、
> 今の行はすべて消え、ファイルの行が新しい行として入る。`tasks` が空なら全部消える。
> 詳しくは[使い方](guide.md#書き出しと取り込み)。

ほかに `settings`・`statuses`・`assignees`・`holidays`・`leaves`・`fields` の部分がある（タスク＋設定で書き出すと入る）。
**ファイルにある部分だけ置き換え、無い部分は今のまま。** `leaves`（休暇）だけは足すだけで、ほかの休暇は消さない。

日数・差異・遅れはファイルに入らない。読みたいときは `GET /api/projects/{id}/grid` が計算済みで返す。

> 読むのは grid、書くのは JSON。

## API

### API トークン

| | 発行する人 | 開けるもの |
| --- | --- | --- |
| プロジェクトの設定 → API トークン | オーナー | そのプロジェクトだけ。「読むだけ」か「読み書き」 |
| 全体の設定 → API トークン | 管理者 | 全プロジェクト |

発行時に一度だけ表示する（保存するのはハッシュ）。

```sh
curl -H "Authorization: Bearer fug_…" \
  https://example.com/api/projects/release-plan/document          # 読む

curl -X POST -H "Authorization: Bearer fug_…" \
  -H "Content-Type: application/json" --data @plan.json \
  https://example.com/api/projects/release-plan/document          # 書き戻す（全置換。確認は出ない）
```

```sh
curl -H "Authorization: Bearer fug_…" https://example.com/api/projects   # 計画の一覧
curl -H "Authorization: Bearer fug_…" https://example.com/api/summary    # 案件ごとの数字
```

| | |
| --- | --- |
| `GET /api/projects/{id}/document` | JSON で書き出す。`?settings=0` でタスクだけ |
| `POST /api/projects/{id}/document` | JSON を取り込む（[全置換](guide.md#書き出しと取り込み)） |
| `GET /api/projects/{id}/grid` | 日数・差異・遅れを計算済みの表（1.0 の約束の外） |
| `GET /api/projects` | 計画の一覧 |
| `GET /api/summary` | 統計画面と同じ計算を、プロジェクト単位で（`late_days + wait_days = slipped`） |

- 他のプロジェクトのトークン、読むだけのトークンでの書き込み、トークンもクッキーも無い要求は、すべて **403**
- トークンで書いた変更は、タスク変更履歴に **`API <トークンの用途>`** として残る
- `/api/projects` と `/api/summary` はログイン中のセッションでも叩けて、その場合は自分が見られるプロジェクトだけが返る
- `/api/summary` の `delayed` は、いま遅れている行（予定遅れ、または終わっていない納期遅れ）の数

## 権限と認証

最初に登録した人が管理者（[README](../README.md#最初のアカウント)）。以降、アカウントを作れるのは管理者だけ。

| ベース権限 | |
| --- | --- |
| 管理者（全体） | 全部。全体の設定・ユーザー・バックアップ |
| 編集者 | 全プロジェクトを編集できる |
| 閲覧者 | 全プロジェクトを読める |
| 無効（招かれたプロジェクトだけ） | メンバーに加えたプロジェクトだけ |

案件ごとに分けるなら、ベースを「無効」にして、プロジェクトのメンバー（オーナー・編集者・閲覧者）に加える。

- パスワードの決まり（最低文字数・必要な文字種・使わせない語）は全体の設定で決める。既定は8文字以上
- パスワードを変えると、その人の他のセッションは切れる
- 初期パスワードは管理者が決めて本人に渡す。忘れたときも管理者が入れ直す（メールは送らない）
- **ユーザーの追加・削除・権限変更**と、**休暇・出社の追加・削除**は、誰がどの計画からやったかと一緒に残る（ユーザーの画面の下）
- 辞めた人は削除でよい。担当者もタスク変更履歴も名前を文字列で持っているので、記録は壊れない

**管理者が入れなくなったら**、サーバーの上で `fugantt --make-admin yamada@example.com`。

会社の認証（LDAP・SAML・OIDC）とは繋がない。必要なら前段のリバースプロキシで認証する。

### 認証なしで動かす

`FUGANTT_NO_AUTH=yes-everyone-on-this-network-can-edit`。
**その URL に届く人は全員が全プロジェクトを読み書きできる。** 動いている間は画面の上に帯が出る。

## 守り

- **変更は自分の画面からだけ受け付ける。** 同じ機械の別のポートや、隣のサブドメインのページから
  送られた変更は 403。ブラウザが付ける `Sec-Fetch-Site`（古いブラウザなら `Origin`）で見分ける。
  API トークンでの呼び出しは対象外
- **リバースプロキシは `Host` か `X-Forwarded-Host` をブラウザが使ったまま渡す。**
  書き換えると、自分の画面からの変更まで弾かれる
- **1回に送れる大きさに上限がある。** ふつうは 1MB、計画の取り込み（JSON）は 64MB、
  バックアップの復元は 1GB。超えると 413
- **ログインの失敗は、ユーザー名ごとに 15 分で 8 回まで。** 送り元のアドレスでも数えるのは fly.io の上だけ
- **ページはほかのサイトの枠に入らず、外のスクリプト・画像・フォントを読まない**
  （`Content-Security-Policy`）。色は `#rrggbb` だけを受け付ける。取り込んだファイルでも同じ
- **クッキーには既定で `Secure` と `__Host-` が付く**

## 1.0 の約束

1.0 からは、**壊さないと約束するもの**をここに書く。

- **データベース**。古いファイルは新しい版でそのまま開ける（起動時に移行する）
- **API**。`/api/projects/{id}/document`（読み書き）、`/api/projects`、`/api/summary`
- **設定**。`fugantt.ini` の書き方と、環境変数の名前
- **コマンド**。`fugantt`、`fugantt start` / `stop` / `status` / `log`、`--config`、`--make-admin`
- **既定のポート 1861**

**画面（島）が使う内部のエンドポイントは対象外**。あれは画面と一緒に変わる。

**やらないと決めたこと**（変える気がない、という意味で、これも約束）

- **Windows の署名は買わない。** 初回の「WindowsによってPCが保護されました」は「詳細情報」→「実行」で進む
- **Docker イメージは amd64 だけ。** Mac はバイナリを使う（arm64 ネイティブ）
- **プロジェクト横断の統計画面は作らない。** 数字は `/api/summary` で全案件ぶん取れる
- **会社の認証（LDAP・SAML・OIDC）は入れない。** 前段のリバースプロキシに任せる
- **削除の取り消しはできない。** 消す前に確認が出る。取り消せるのは値・行の追加・並べ替え
- **計画を開くときは全部送る。** 1万行で 170ms、1回きりの費用

**測った事実**（保証ではなく、時間の節約のために）

- 1セル直したときの往復は、100行でも1万行でも **14ms**（release、実測）
- 打鍵（↓キー1回）のブラウザ側の処理は、100行でも1万行でも **15ms**（2026-08-16、release、実際のブラウザ。`web/test/measure.mjs`。測った機種は記録していない）
- ブラウザのテストは Chrome で実際に動かしている（384件）
- 1プロセス、SQLite のファイル1つ。同時に何人まで、という上限は設けていない
