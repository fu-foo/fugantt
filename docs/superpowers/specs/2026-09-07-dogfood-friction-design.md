# ドッグフードで出た8件 — 設計

2026-09-07。v1.0.0 に向けて実際の業務データを入れて使った結果、出てきた8件をまとめて直す。
宿題リスト（README の「v1.0.0 の約束」）は 0.6.0 で空になっているので、これは
「約束の穴」ではなく **手が止まるところ** の話。

いくつかは同じ形をしている——**一打余分にかかる**。納期しかないタスクに嘘の予定を
置かされる、日付に月と年を打たされる、選択とは別にもう一手だけ編集を開かされる。
机上の設計レビューでは出ない種類で、何十行も入れて初めて「これ毎回やってるな」になる。

## 全体を貫く原則

**システム最適よりも、人間が理解できるように動く。** 説明できない動きは、正しくても邪魔。
理屈の上で賢い挙動より、次に何が起きるか読める挙動を取る。6番（列幅）はこの原則の
直接の帰結で、5番・7番の判断もここから来ている。

もう一つ。**原因を突き止めて直す道と、原因ごと無くす道があるなら、後者を取る。**

## 1. 納期

### 決めたこと

**納期は予定と排他にしない。独立した日付として足す。**

「大半のタスクは納期があれば十分」だが、「納期は先だけど、この期間で作業したい」もある。
1行に両方要る。

ただし2つは競合する終了日ではない：

- **納期＝約束**。動かせない。守れたかどうかだけを言う。
- **予定＝段取り**。自分の都合で動かす。いつ手を動かすか、誰の何日を使うかを言う。

問いが違うのでものさしが2本あってよい。破れるのは**どの数字をどちらで測るかを決めずに
両方置いたとき**だけなので、そこを一度だけ決める。

| 数字 | ものさし |
| --- | --- |
| 納期に間に合うか | 納期だけ |
| 段取りから遅れているか | 予定進捗と予定終了 |
| 稼働・空き検索の日数 | 予定バーだけ。納期しかない行は0日 |
| 予定進捗（targets） | 予定バー（現状のまま） |

**フォールバックはしない。** 納期の無い行は納期遅れ列が空、予定の無い行は予定遅れ列が空。
列ごとに1本のものさし、行ごとに「判定なし」がある、で筋が通る。

「納期しかない行は空き検索で0日」は正しい。いつやるか決めていないなら、押さえた日は無い。
日数を数えたければ予定を置く。

### 遅れの列は2本に分ける

いまの「遅延」列は既に2つの事実を混ぜている（`web/src/grid.ts` の `behind()`：
`task.delayed || task.overdue > 0`）。ここに納期を足すと1列で3つになる。

ただし `delayed`（予定進捗に届いていない）と `overdue`（予定終了を過ぎて終わっていない）は
**同じものさし＝段取り**で測っている。別なのは納期だけ。だからこう割る：

| 列 | 何を言うか | ものさし |
| --- | --- | --- |
| **予定遅れ**（いまの「遅延」を改名） | 予定進捗に届いていない／予定終了を過ぎて終わっていない | 段取り |
| **納期遅れ**（新設） | 納期を過ぎて終わっていない／実施終了が納期より後 | 約束 |

実務で聞く質問がそのまま両方引ける：「納期に間に合わないものを出して」＝納期遅れが遅れ、
「段取りから遅れているものを出して」＝予定遅れが遅れ。

1列に畳んで値を「納期遅れ／予定遅れ／順調」にする案は却下。両方に当てはまる行が片方しか
名乗れず、2本目の質問が正しく引けない。

改名しても列の並び順は壊れない（保存は key `"late"` で、ラベルではない）。辞書の鍵が
日本語なので `src/i18n` の該当分は入れ替えになる。

### ついでに直す食い違い

セルは `delayed || overdue > 0` で「遅延」と出すのに、絞り込みの「遅れ」は `task.delayed`
だけを返す（`grid.ts` の `matches()`）。**予定終了を過ぎているだけの行は、画面に遅延と
出ているのに、遅れで絞ると出てこない。** 同じ場所を触るので一緒に直す。

### チャート

**▼ を行の上端に置いて、下向きに納期の日を指す。** バーには重ねない。予定終了と納期が
同じ日でも、バーの端と ▼ がぶつからない。

```
 ▼                        ← 11/30 納期
 ████████░░░              ← 11/10〜11/25 予定
        ↑ここが余裕
```

- 納期しかない行は ▼ だけ。`renderBar` は `if (!planned && !actual) return row;` で
  早期に抜けるので、ここを通す。
- 納期遅れの行は ▼ が遅延色（バーの `is-delayed` と同じ扱い）。
- **▼ はドラッグしない。** 予定バーは掴んで動かせるが、納期は約束。入力はチャートの
  右クリック（0.7.0 で全部入るようにしたメニュー）から。

**チャートの窓に納期を入れる。** `src/domain.rs` の `window()` は予定と実施の最初と最後から
窓を決めているので、**全バーより先にある納期は窓の外に落ちて描かれない**。納期タスクは
「先の日付」が本業なので必須。

### 集計行

既存の規則をそのまま踏む。

- **納期の値**＝子の最大（`end` が子の最大なのと同じ。`domain.rs` の `rollup()`）。読み取り専用。
- **納期遅れ**＝子のどれかが納期遅れなら遅れ（`delayed` が `any` なのと同じ）。

2つ目が大事で、**集計行の納期から計算し直さない**。子が 10/5 と 11/30 の納期を持っていて
10/5 が飛んだとき、親の納期（11/30）から計算すると12月まで何も出ない。子から吸い上げれば
10/6 から親が赤くなる。いまの `overdue`（日数の積算）も `delayed`（any）も子から吸い上げていて、
親自身の日付から計算し直してはいない。

納期遅れは**真偽だけ**持つ。何日超えたかは葉のホバーに出す。

### 列の位置と入出力

`タスク | 予定遅れ | 納期遅れ | 担当者 | ステータス | 納期 | 予定開始 | 予定終了 | …`

遅れ2本はタスク名の隣（「遅延は名前の隣にあるべき」で既にそう置かれている）。納期は
**予定開始より前**——大半の行は納期しか埋まらないので、いちばんよく埋まる列が先に来る。
読む順も「いつまでに → いつやる」で合う。

保存済みの並び順は心配ない。`column_order`（`src/project.rs`）が**宣言された位置に差し込む**
作りで、末尾に落ちない。`ROLLED_UP` に納期を足せば集計行が子から取る。

- 入力：表のセルは `kind: "date"`（既存のエディタと日付ピッカー）。チャートの右クリックに
  「納期」を足す。書き込みは島の内部エンドポイント＝**v1 の約束の対象外**。
- 書き出し：`/api/projects/{id}/document` は**約束の対象**なので、任意フィールドを
  **足すだけ**。無ければ空として読む。既存の書類はそのまま読める。JSON（`src/interop/json.rs`）と
  Excel（`src/interop/xlsx.rs`）にも列を足す。
- 統計の「遅延」件数（`src/project.rs`）に**納期遅れも数える**。数えないと、大半のタスクが
  納期だけになったとき統計が空になる。
- 絞り込みは自動で付く。納期は日付列なので ≧/≦（「今月中の納期だけ」）、納期遅れは 遅れ／順調。

### 検討して捨てた案

- **納期＝予定開始のない予定終了（排他）**：「納期は先だけど今週やりたい」が置けない。
- **既存の予定終了を納期と読み替え、作業期間を別に足す**：既存の全計画の `end_date` が
  黙って「約束」に変わる。
- **独自項目の日付で持つ**：派生値（遅れ・▼・絞り込み）が一切効かない。

## 2. 日付の速記

### 決めたこと

| 打つ | 読み |
| --- | --- |
| `5` → `05` | 当月5日 |
| `12` | 当月12日 |
| `305` → `0305` | 当年3月5日 |
| `1225` | 当年12月25日（既存） |
| `20261225` | そのまま（既存） |

桁数だけで決まるので迷いがない。`12` は12日、`1225` は12月25日。5〜7桁は今まで通り読まない
（6桁を YYMMDD と読む案は、当年が既定なので要らない）。存在しない日は今まで通り弾く
（`2/31` を null にする往復チェックが既にある）。

**繰り上げはしない。** 12/28 に `3` と打てば 12/03、つまり過去。来月へ送らない。
実施開始・実施終了は過去を入れるのが普通で、勝手に送ると「昨日」が打てなくなる。

### 「当月」「当年」の出どころ

いまブラウザ側は `new Date().getUTCFullYear()`（`grid.ts` の `flexibleDate`）。**UTC なので、
日本時間の毎月1日 0:00〜9:00 は前の月**になる。年も元日の9時間ずれる。4桁入力のときだけ効く
「年」の話だったので目立たなかったが、当月を足すと**毎月1日に効く**。

サーバが渡している `today`（`GridData.today`）を使う。派生値はサーバが持つ、の原則どおりで、
サーバ側 `flexible_date`（`src/api.rs`）と日付の起点が揃う。

### 変える場所

`flexibleDate`（`web/src/grid.ts`）と `flexible_date`（`src/api.rs`）は「同じ読み方をする」と
約束して書いてあるので、**常に一緒に変える**。

効くのは4か所：セルの編集、絞り込みの箱（いまは8桁だけ特別扱いしているので `flexibleDate` に
一本化）、待ちのダイアログ、予定進捗のダイアログ。休暇のダイアログはネイティブの
`type="date"` なので対象外。

## 3. 常時編集

### 決めたこと

**セルを選択したら、そのまま編集モードに入る。** ダブルクリック／Enter／打鍵で開く一手を無くす。
対象は**全部の列**（ステータスの `<select>`、日付のカレンダー釦も含む）。

ただし**ダイアログ列は開かない**。`startEdit` は既に待ちと予定進捗をダイアログへ逃がして
`editing` を立てずに返る。7番でコメントが3つ目になる。規則はこう：

> **選択で自動的に開くのは普通の列だけ。ダイアログ列（待ち・予定進捗・コメント）は、
> Enter・F2・セルの釦・右クリックで明示的に開く。**

頼んでいないのにダイアログが出ることは無い。

キーはこうなる：**Tab／⇧Tab で左右、Enter で確定して下、↑↓ で確定して上下、←→ はキャレット、
Escape で元の値に戻す**。左右のセル移動が Tab だけになるのは受け入れる（本人合意済み）。

### 巻き込みで直すもの（6か所）

実装の軸は「**編集中は全部やめる**」を「**編集中のセルだけ避ける**」に置き換えること。

1. **他人の変更が届かなくなる（本命）。** `follow()` も `refresh()` も先頭で
   `if (this.editing) return;` して丸ごと降りる。常時編集だと `editing` がずっと真になり、
   **カーソルを置いたまま席を立つと他人の変更が一切入らない**。画面は普通に見えているので
   気づけない。`applyPatch` / `repaintRows` が編集中のセルだけ避ける形に変える。
2. **⌘Z / ⌘Y が行の取り消しに届かない。** 編集中の ⌘Z は入力欄自身の取り消しになる。
   合間が無くなるので、**入力欄が未編集なら grid の取り消しに回す**ように横取りする。
3. **↑↓ でのセル移動。** `onEditKeyDown` は Enter・Tab・Escape しか見ていない。
   ↑↓ を足して「確定して上／下」にする。
4. **Escape の行き先。** いまは「編集を捨てて選択に戻る」。戻る先が編集なので、
   「編集前の値に戻して、編集は続く」に変える。
5. **チャートのクリックと右クリック。** `renderBar` の `mousedown` / `contextmenu` が
   `if (this.editing) return;` で降りる。常時編集だと**チャートを押しても選択されず、
   右クリックのメニューも出ない**。0.7.0 で入れた「チャートから全部入れられる」が丸ごと死ぬ。
6. **打てないセル。** 集計行の集計列、権限、その他（0.6.1 の4種類の理由）。選択しても編集に
   入らない行が混じる。理由が出るので説明はつく。許容。

### 消せるもの

いまは選択中かつ非編集のときだけ透明な入力欄（`renderTypist`）を置いて打鍵を拾っている。
常時編集なら要らない。**ホイールで縦スクロールできなくなった 0.4.7 のバグの正体がこの
置きっぱなしの入力欄**だったので、消えるのは素直に良い。

### 心配しなくていいこと

素通りしても書き込みは飛ばない。`commitEdit` は `value === this.cellText(task, column)` で
降りる。50行なぞっても変更履歴は汚れない。

## 4. 行の色を左ペイン全体に

行の色は「区切り」として使われている。いまはタスクのセルにしか色がつかない。

**原因**：色は行に乗っている（`grid.ts` が `--fg-row-bg` を行に立てる）のに、それを背景に
使っているルールが `.fg-row .fg-cell.is-frozen { background: var(--fg-row-bg) }` の1本しかない。
`.fg-row` 自身には `background` が無い。**固定列（既定ではタスク名）だけが塗られて、
残りは透明**。

**直し**：`.fg-row` に `background: var(--fg-row-bg)` を足す。固定列のルールは残す
（他の行の上を滑る列は自前の不透明な塗りが要る）。チャート側は別クラス（`.fg-bar-row`）なので
巻き込まない。

**同じ罠が2つ待っている**（0.7.1 で踏んだ「選択中のセルが行の文字色を失う」と同型）：

1. `.fg-row.is-current { background: #f8fafc }` と、暗い画面の `background: var(--row-current)`
   が**直の色**。行に背景を持たせた瞬間、**カーソルのある行だけ塗った色が消える**。
   塗った行では `--fg-row-bg` を勝たせる。
2. `.fg-cell.is-selected { background: #eff6ff }` は既に
   `.fg-row.is-painted .fg-cell.is-selected` で手当て済み。そのまま効く。

**チャート側は塗らない。** あちらは土日・祝日・今日の色が既に載っていて濁る。区切りは
左ペインで止まる。6番で全列固定になると表の右に余白が出るが、行の背景はそこまで届くので
帯としては切れない。

## 5. 列幅を掴んで一時的に変える

「ちょっと今はこの幅で見たい」ができない。プロジェクト設定としての列幅は既にある
（`column_widths`、設定画面で px 指定・空欄で自動）。足りないのはその場でつまむ道。

- 見出しセルの右端に掴み手。`cursor: col-resize`。表とチャートの間の `.fg-splitter` と
  同じ作りでいい（`touch-action: none` 含め、動いているものが横にある）。
- 幅の決まる場所は1か所（`grid.ts` の `tracks` を組むところ）。
  `this.widths[key] ?? data.column_widths[key] ?? TRACKS[column.kind]` にすれば、
  見出し・フィルタ行・データ行の全部に回る（どれも見出しの `gridTemplateColumns` を写している）。
- 引いている間はトラックを直接書き換えるだけで再描画しない。離したときに `this.widths` へ入れる。
- **`pinColumns()` を呼ぶ。** 固定列の `left` は実測で決まっている。幅を変えた後に呼ばないと
  **固定列が重なる**。引いている最中の毎フレームと、離したときの両方。
- **最小幅 40px。** 0まで詰められると押せないセルができる。
- **掴み手のダブルクリックで既定に戻す。** 一時的な幅なので、戻る道が無いと詰まる。

**保存する。** ペイン幅が既に `localStorage`（`PANE_KEY`）にブラウザごとに保存されているので、
列幅も同じ棚に置く。プロジェクト設定（全員に効く）とは別の、自分のブラウザだけの上書き。

### スプリッターの上限

左右のスプリッターが半分あたりで止まるのは、**固定値**のせい：

```ts
this.paneWidth = clamp(startWidth + move.clientX - startX, 160, 1200);
```

上限 1200px 決め打ち。2560px の画面ならちょうど半分あたり。**画面が広い人だけが踏む**。

一方、自動で幅を決める側にはちゃんとした規則がある：`Math.max(320, grid.clientWidth - 480)`
——「チャートに必ず 480px 残す」。手で引くときだけこの規則ではなく 1200 という数字が効いている。

**上限を `grid.clientWidth - 480` に揃える。** 「チャートがこの道具の主役」という既存の判断と
一致し、直しは1行。下限 160px は据え置き。

## 6. 列幅の既定 — 伸びる列をゼロにする

### 決めたこと

**全列を固定幅にする。伸びる列は1本も残さない。タスク名は 18rem。**

理由は原則そのもの。中身やスクロール位置で幅が動くと「なんでそういう動きするねん」になり、
説明できても邪魔。

### いま何が起きているか

幅は**列ごとではなく種類ごと**に決まっている（`TRACKS`）。`text` と `select` が
`minmax(5rem, 0.8fr)` / `minmax(5rem, 0.6fr)` で伸びる側なので、遅延・担当者・予定進捗・待ち・
コメントの5列が余った幅を山分けする。伸びてほしいのはコメントだけなのに、種類で決めているので
全部伸びる。これが「遅延と担当者が幅ありすぎ」の正体。

さらに、スプリッターを一度も引いていないと `--fg-pane-width` は `auto` で始まり、1フレーム後に
実測した px に差し替わる。`.fg-grid` は描画のたびに作り直されるので、その px は毎回消えてまた
`auto` から測り直しになる。測っているのは DOM にいる行だけ＝**仮想スクロールなので見えている行だけ**。
`auto` の下では `1.6fr` が中身に効くため、**いま画面にある行の中でいちばん長いタスク名が幅を決める**。
これが「縦スクロールすると列幅が変わる」の筋。

### 直し

全列を固定にすると、**中身に反応するトラックが1本も無くなり、この症状は原因ごと消える**。
「一度だけ測る」という手当ては要らない（測っても毎回同じ値になる）。

| 列 | 幅 |
| --- | --- |
| タスク名 | **18rem** |
| 遅延（予定遅れ）・納期遅れ・担当者・ステータス・予定進捗・待ち | 5.5rem |
| コメント | 12rem |
| 日付（納期・予定・実施） | 6.5rem（現状） |
| 日数・差異・進捗 | 現状のまま |

`TRACKS` の `text` と `select` を固定にする。コメントは列ごとの上書き（`ColumnDef` に任意の
`width`）で 12rem。**独自項目の文字列も一緒に固定になる**——独自項目が2つ3つある計画で
画面を取り合う状態が消えるので、これも良い方向。個別に広げたければ列ごとの上書きで足せる。

**代償**：予定進捗（`8/20 30%, 8/28 100%`）と待ち（`8/1〜8/5`）は 5.5rem だと「…」で切れる。
ただし空の行が大半で、必要なときは掴んで広げられる（5番）し、いつも使うなら設定に px を書けば
全員に効く。既定は「よくある行」に合わせる。

ペインが表の合計幅より広ければ右に余白が出る。これは許容する（4番の行の色はそこまで届く）。
狭ければ横スクロール——固定列が既にその前提で作られている。

## 7. コメントをダイアログ入力に

使ってみるとコメントをしっかり書くことが多く、1行では足りない。

### まず確認した制約

**行の高さは可変にできない。** 仮想スクロールが `rowPixels`（1行だけ測った高さ）× 行番号で
位置を出している（`measureRows` / `rowWindow`）。高さが行ごとに違うと窓の計算が全部ずれて、
行が本来と別の場所に描かれる。「コメントの行だけ背が高い」は無し。

### 決めたこと

**入力はダイアログ、表示は1行。** コメントは待ち・予定進捗に続く**3つ目のダイアログ列**になる。

- `startEdit` は既に待ちと予定進捗をダイアログへ逃がして `editing` を立てずに返る。
  コメントを同じ扱いにするだけ。
- 開き方：Enter・F2・セル右端の小さな釦・右クリックメニュー。チャートの右クリックから
  コメントを入れる道（0.7.0）も同じ箱に繋ぐ。
- 中身は `<textarea>`。
- 表示（非選択時）は1行。改行は HTML が空白に潰すので「一行目 二行目…」と続いて見え、
  入りきらなければ「…」。全文はホバー。
- セルには待ち・予定進捗と同じ形の小さい釦を出す。
- 保存先は `tasks.note` のまま。**スキーマ変更なし**（SQLite の TEXT は長さを問わない）。

### これで消える危険

`<input>` は改行を持てない。値に `"一行目\n二行目"` を入れると改行が消える。もし
コメントをインラインの常時編集にしていたら、**何も打たずに Tab で通り過ぎただけで、改行が
消えた値が書き戻される**（`commitEdit` は「値が違う」と判定して送る）。ダイアログ列にすれば
`<input>` がコメントを持つ場面が一度も無くなるので、この危険は起こらない。

### 細部

- 変更履歴は200文字で切れる（`src/history.rs` の `truncate`：
  「A note's worth of text is history; a pasted document is not.」）。元からの設計、そのまま。
- **Excel 書き出しは折り返し指定が要る**（`src/interop/xlsx.rs`）。付けないと改行のあるセルが
  1行に潰れて見える。

## 8. 自動算出で打てない場所を分かるようにする

予定日数のように、計算結果で入力できないセルが、打ってみるまで分からない。

### いまの状態

打てない理由は4つある（`grid.ts` の `refusal()`）が、**印がついているのは1つだけ**。
集計行の派生セルにハッチが入る（`is-derived`）。日数・遅延・差異には何も無い。

そうした理由もコードに書いてある：

> Hatching means "this row's value comes from its children", not merely "read-only" —
> otherwise the always-derived day count would stripe every row and the signal would
> stop meaning anything.

これは正しい。**印の付け場所が違うだけ**。日数・遅延・差異は「この行が計算結果」ではなく
「**この列がまるごと計算結果**」。列の性質なら、1万回セルに描くのではなく見出しに1回言えばいい。

実際 `refusal()` の最初の3つは `task` を一切見ていない。**行を読まない拒否＝列ぜんぶ自動**、と
機械的に判定できる。

### 決めたこと

範囲ごとに印を1つずつ。

| 理由 | 範囲 | 見せ方 |
| --- | --- | --- |
| 日数・遅延・差異（予定遅れ・納期遅れ） | 列ぜんぶ | **見出しの文字を淡くする＋ホバーで理由の文**（新規） |
| 集計行の日付と進捗 | 行×列 | いまのハッチ（そのまま） |
| このプロジェクトは読むだけ | 画面ぜんぶ | 一度だけ画面の端に（現状を要確認） |

ホバーに出す文は `refusal()` が既に持っているものをそのまま使う（「日数は日付から数えます。」など）。

**セル本体には手を入れない。** 理由は2つ：

1. 「まだらにならない」という既存の判断がそのまま生きる。
2. 4番で行に色がつくので、セルの文字色や背景をいじると塗った色と喧嘩する——0.7.1 で踏んだ罠を
   もう1つ増やすことになる。見出しなら色の話と交わらない。

**幅を食わない案を選んでいる。** 予定日数は 5.2rem しかないので、ラベルの後ろに記号を足すと
「予定日数」が押し出される。淡くするだけなら1pxも食わない。足りなければ後から記号を足せる。

### 3番との関係

常時編集にすると、**打てるセルは乗った瞬間に入力欄になる**ので、打てないセルは「何も起きない」
ことで自然に分かる。見出しの印はその補強。逆に言えば、常時編集を入れるからこそ、この対比が
毎回目に入るようになる。

## テスト

**ブラウザで実際に動かして確かめる。** 「存在する」はテストではない。

0.7.2 の教訓を繰り返さない——**テストが337件あって半年見逃した理由は、全部が既定の幅で
回っていたから**。今回は幅と列に触るものが多いので、**既定でない値でも回す**：

- 列幅を既定から変えた状態で、行の色が全列に届くか（4番）
- 掴んで幅を変えた後に固定列が重ならないか（5番）
- タスク名が長い行と短い行を混ぜて縦スクロールし、**列幅が1pxも動かないこと**（6番）
- 日の幅を既定から変えた状態で ▼ が正しい日に立つか（1番、0.7.2 のずれと同じ測り方：
  今日の印の `style.left ÷ 列のピッチ` で原点の日を逆算して日数で比べる）

他人の変更が届くこと（3番の1）は**2つのブラウザ**で確かめる。片方でカーソルをコメント欄に
置いたまま、もう片方で編集して、届くこと。ここは黙って壊れるので、テストが要る。

日付の速記（2番）は「当月」が絡むので、**月初の境界**を含めて server 側の単体テストで押さえる。

見出しの印（8番）は、**列を隠した状態・並べ替えた状態**でも自動算出の列すべてに出ていることを見る。

---

## やらないこと

- **▼ のドラッグ**。約束は掴んで動かすものではない。必要になったら後から足せる。
- **チャート側に行の色を敷く**。土日・祝日・今日の色と濁る。
- **行の高さを可変にする**。仮想スクロールが壊れる。
- **納期と予定遅れを1列に畳む**。2本目の質問が引けなくなる。
- **列幅の「一度だけ測る」手当て**。6番で原因ごと消えるため不要。
- **自動算出のセル本体に印をつける**。まだらになり、行の色とも喧嘩する。印は見出しに1つ。
