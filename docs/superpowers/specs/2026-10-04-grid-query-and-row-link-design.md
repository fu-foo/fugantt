# グリッドに条件と行のリンクを渡せるようにする — 設計

2026-10-04。`fu-gantt-web` のグリッドに、ホストが指定できる属性を2つ足す。fugantt は v1.2.0。
fugantt 自身の画面と挙動は変えない。

## なぜ要るか

グリッドを組み込む2つめのアプリ（fuirori、Redmine 様の課題管理）で、次の2つができない。

1. **絞り込んだ結果をガントで見る。** fuirori では、課題の一覧で絞った条件（未完了、担当など）の
   ままガントを開く。条件を解釈するのはサーバーだが、グリッドは `基点/grid` を固定で叩くので、
   条件を伝える手段が無い。
2. **行から課題の詳細に飛ぶ。** グリッドの行は課題で、説明やコメントは別のページにある。
   いまのグリッドには、行から外のページに出る入口が無い。

どちらも「ホストが属性で渡し、無ければ何も変わらない」形にする。`data-api` と
`data-filter-count` を足したときと同じ考え方。

## 足す属性

```html
<div id="fugantt-grid"
     data-project="abc"
     data-api="/projects/abc/gantt/api"
     data-query="status=open&assignee=佐藤"
     data-row-link="/issues/by-id/{id}"></div>
```

### `data-query`

グリッドが送る **すべての** リクエストの URL に、クエリーとして付ける。

- 対象は `fetch` で送るもの全部と、`live` の `EventSource`
- 読み取りだけでなく書き込みにも付ける。書き込みの応答（`Mutation`）は計画の全体か差分を
  返すので、サーバーはどの条件で見ているかを知る必要がある
- 値はそのまま `?` の後ろに付ける。エンコードはホストの責任（ホストが組み立てた文字列を、
  グリッドは解釈しない）
- 先頭の `?` と `&` は落とす。空、または空白だけなら何も付けない
- 属性が無ければ、URL はこれまでと1文字も変わらない

グリッドの中の URL には、いまクエリーを持つものが無い。組み立てを1か所の関数に寄せ、
そこで付ける。

### `data-row-link`

行から外のページに飛ぶリンクの雛形。`{id}` を、その行の id（URL エンコードしたもの）に
置き換える。

- 件名のセルの、件名の後ろに小さなリンクを出す。表示は `↗`、`title` と `aria-label` は
  「開く」（英語の画面では "Open"）
- 押すと、同じタブでそのページに移る。ブラウザーの普通のリンクなので、Ctrl／Cmd を押しながら
  なら別のタブで開く
- リンクを押しても、セルの選択や編集は始まらない（押下をグリッドの処理に渡さない）
- `{id}` を含まない雛形は、全部の行が同じ行き先になる。それはホストの指定どおりなので
  そのまま使う
- 雛形が `http:`・`https:` で始まるか、`/` で始まるときだけリンクを出す。それ以外
  （`javascript:` など）は無視して、リンクを出さない
- 属性が無ければ、何も出ない。DOM もこれまでと同じ

キー操作での入口（選んだ行を開くキー）は足さない。必要になってから決める。

## 変えないもの

- fugantt のページは2つの属性を付けない。画面も通信もこれまでと同じ
- API の JSON の形（`fu-gantt-core` の `wire`）は変えない
- グリッド自身の絞り込み（画面内の絞り込みと、条件に名前を付けて残す機能）はそのまま

## 文書

`docs/gantt-api.md` の属性の表に2行足す。あわせて次を書く。

- `data-query` を使うホストは、条件から外れた行の扱いを決める必要がある。差分（`Patch`）の
  `total` は「その条件で見えている行数」にすること。グリッドは手元の行数と比べ、合わなければ
  全体を読み直す
- `LiveChange`（他の人の変更の通知）は条件を知らない。通知を受けたグリッドは、条件付きの
  URL で読み直すので、ホストは `patch` と `grid` の両方で条件を解釈すること

## 確かめ方

- **URL の組み立ての単体テスト**（ブラウザー不要、`web/test/base.test.mjs` に足す）
  - 条件なし: これまでと同じ URL
  - 条件あり: `?` で付く。先頭の `?`・`&` と前後の空白は落ちる
  - 空と空白だけ: 何も付かない
  - 行のリンク: `{id}` が置き換わる。id は URL エンコードされる。`{id}` が複数あれば全部
    置き換わる。`javascript:` で始まる雛形はリンクにならない
- **見本のホスト**（`examples/minimal-host`）に2つの属性を付ける
  - 煙テスト: 条件を付けたリクエストをサーバーが受け取れる（条件に合う行だけ返す）
  - ブラウザーテスト（`web/test/host.test.mjs`）: すべての API リクエストに条件が付いている。
    行のリンクが出て、行き先が雛形どおり
- **fugantt が変わっていないこと**
  - 突き合わせテスト（`apps/fugantt/tests/golden.rs`）が一致する
  - グリッドのブラウザーテストが、変更前と同じ結果になる（383 通過、もとから落ちている
    1件はそのまま）

## 失敗したときの扱い

- 属性なしの経路で URL や DOM が変わっていたら、それは不具合。属性なしのときの URL が
  これまでと同じであることは単体テストで、DOM と挙動が同じであることはブラウザーテストで
  固定する
